# MiseDeck — 产品逻辑

> [English](../../../docs/design/product-logic.md)

状态：产品负责人已确认（beta.3 反馈轮，2026-09）。本文档是**产品展示什么、如何行为**的唯一事实来源。视觉样式见 `docs/design/visual-language.md`；领域词汇见 `CONTEXT.md`；三条产品原则见 `AGENTS.md`。

## 定位

MiseDeck 是 **mise CLI 的 GUI 版**。它的目的不是取代终端，而是**教会你终端**：每个界面都是真实 mise 命令面的投影，只用鼠标点点点的用户也会逐渐学会他本可以敲出的命令。

北极星感受：*「我永远知道这个界面对应哪条 mise 命令。」*

## 指导方针

1. **导航镜像 mise 的支柱。** mise 是「按项目管理 dev tools、env vars、tasks」。侧边栏主组就是这三样，外加目录视角（预览）和扩展面（插件）。除此之外没有东西配得上顶级槽位。
2. **不发明概念。** 一个页面存在的唯一理由是有 mise 命令（或命令族）背书。页面名词动词一律取自 `CONTEXT.md` / mise 自己的 CLI 词汇（`use`、`install`、`set`、`run`、`trust`、`doctor`……）。
3. **命令永远可见。** 每个页面头部标明本页对应的 CLI 等价命令（如 Tools → `mise ls` / `mise use`）。所有变更操作仍流经执行面板、展示真实 argv（AGENTS.md 不可妥协项）。
4. **框架让位给内容。** 导航是可折叠侧边栏；目录指示条只在需要时出现；执行面板只在有命令运行时出现；纯展示页不带执行面板。
5. **数据是数据，标签是标签。** 排版样式（大写、字距）只能用于标签，永远不能用于数据——路径、版本号、命令、参数值一律按 mise 报告的原样渲染。
6. **视觉继承。** light 和 dark 两个主题都跟随 mise.jdx.dev 的视觉风格，让应用读起来是 mise 家族的一员，而不是又一套千篇一律的极客皮肤。

- **Styleguide** 从产品导航移除；路由仅在开发模式下保留。

## 页面清单（目标状态）

| 页面 | 背书的 mise 命令 | 承载的工作流 |
|---|---|---|
| 首页（点品牌区） | `mise version`、`mise self-update`、安装脚本 | mise 在不在？装它/更新它 |
| 预览 | `mise -C <dir> ls` + `mise env` + `mise config`（文件优先级）+ `mise.lock` | 「mise 在这个目录解析出了什么」——解析后的工具、环境变量、按优先级加载的配置文件、lockfile；信任状态浮出 |
| 工具 | `mise ls`、`mise ls-remote`、`mise use`、`mise install`、`mise uninstall`、`mise upgrade`、`mise outdated` | 已安装 ≠ 已激活；切换/安装/升级/卸载 |
| 环境变量 | `mise env`、`mise set`、`mise unset` | 环境变量是一等公民，按目录或全局 |
| 任务 | `mise tasks ls`、`mise run`、`mise tasks add/edit` | 列出、运行、轻编辑当前目录的任务 |
| 插件 | `mise registry`、`mise plugins ls` | 浏览 shorthand → backend；已安装插件 |
| 诊断 | `mise doctor` | 健康检查 |
| 设置 | `mise settings ls/set/unset` | 编辑 mise 设置 |

**Config 编辑器页解散。** 它把两个一等概念揉在一起，还和 Tools 页重叠：

- 它的 `[tools]` 编辑 → 已存在于**工具**页（`mise use` / `--remove`）；
- 它的 `[env]` 编辑 → 成为独立的**环境变量**页（`mise set` / `mise unset`）；
- 配置文件可见性（加载了哪些文件、优先级顺序、文件内容）→ 并入**预览**页（`mise config`），因为「mise 在这里看到了什么」正是预览的职责。

`/config` 路由先重定向到 `/preview` 一个版本，随后移除。

## 交互规则

1. **执行面板按需出现。** 默认隐藏；有命令运行时滑出（真实 argv + 实时日志），空闲时可收起，任何页面可重新打开。没有任何变更操作的页面（诊断、预览的信任按钮之外、插件）永不出现执行面板。所有变更仍必须经过它——变的只是可见性，契约没变。
2. **信任与激活横幅留在页内。** `mise trust` 和 `mise activate` 是 mise 自己的门槛；横幅在它们挡住用户的地方出现（预览/工具/环境变量/任务/设置；激活横幅全局但可关闭）。
3. **窗口纪律。** body 永不横向滚动；天然很宽的内容（JSON、表格、日志）在各自容器内滚动。窗口有最小尺寸；默认尺寸和最小尺寸需内容感知——具体机制（运行时测量 vs 设计期常量）是开放问题，留给实现 ticket。
4. **目录上下文只有一个来源。** 指示条是选择/展示目录的唯一位置；每个页面消费它（`mise -C <dir>`），任何页面不得硬编码目录（architecture.md）。
5. **i18n 全覆盖。** en + zh-CN 承载所有文案；语言菜单是唯一的语言控制。
6. **空状态也要教学。** 没有内容可展示的页面（未选目录、无工具、无任务）要写明哪条命令能填上它。
