# UI/UX 规则

> [English](../../docs/design/ui-ux-rules.md)

MiseDeck 每个页面、组件、样式和文案都必须遵守的交互与呈现规则。`visual-language.md` 管 token（色彩、字体、间距、动效）；本文档管*行为*。两份文档都沉淀自真实的 beta 反馈周期——下面每条规则的存在，都是因为它的违例曾经发布过、由人类揪出来的。豁免 token 规则的书面约定（见「布局与排版」）：1px 边框和 4px 小元素圆角。

## 一问测试

发布任何界面前问一句：**一个 mise CLI 用户能预测这个界面做什么吗？**（ADR-0004。）如果答案需要 CLI 里没有的产品知识，那就是设计错了，不是用户错了。

## 数据诚实

- 数据按 mise 报告的原样渲染。路径、版本号、后端名、别名、命令名、标识符保留原始大小写——`vfox:mise-plugins/vfox-1password` 原样呈现。大写 + 宽字距只属于小节眉签（见 `visual-language.md`）：其余标签一律正常大小写，数据则两者都不沾。用户输入也必须原样回显：键名输入框里 `myVar` 就显示 `myVar`，绝不显示成 `MYVAR`——把大小写敏感的输入视觉大写化，等于 UI 在对存储值撒谎。
- 大写/宽字距永远不得落在数据上，包括通过继承落入：`text-transform` 和 `letter-spacing` 会继承，所以任何渲染数据的组件（EmptyState、Badge、表格单元格）当祖先可能带标签样式时，必须在自身根元素复位 `text-transform: none; letter-spacing: normal`。防御点在被包裹的组件，而不是每个调用处。
- 缺失数据渲染为 `—`，或者撤掉该列。绝不用硬编码或编造的值填列——错误的事实比没有事实更糟。
- GUI 镜像 CLI 默认行为时（如 `mise settings ls` 只显示显式设置的键），保持 CLI 行为为默认；更宽的视图只能是带 flag 标注的显式开关（`--all`）。

## 教学性

- 每个变更操作都展示真实的 mise 命令——包括确认框。确认框是教学时刻：「将运行 `mise uninstall go@1.27.0`」。
- 空状态在 GUI 内引导：给出按钮，或直接展示全局解析结果。一个让用户「去跑 CLI 命令」的空状态是失职的。
- 长结果列表（查询、日志、版本）可清空，超过 ~10 行即分页：先渲染 10 行首页并展示分页器（上一页 / 第 X / Y 页 · 共 N 条 / 下一页 / 跳转到指定页），不再折叠为「展开全部 N 条」。每页大小为自由数字输入，下限 10。
- 页面的命令提示列出且仅列出该页面能运行的 mise 命令——不多（编造的命令是 bug），不少（加了功能不更新提示也是 bug）。只列用户面向的命令：GUI 为自己的取数通道传的内部参数（`--json`、`--json-extended`、`--path` 等）绝不出现在提示里。顺序遵循页面从上到下的布局。提示一律经由共享的 `CommandHint` 组件渲染——只有一份实现，不允许各页自抄——组件将提示限制在 `max-width: 60ch`，并把每条命令视为不可拆分的最小单元：折行只发生在命令之间，绝不从命令中间断开（beta9）。

## 交互完整性

- 破坏性操作（卸载、取消设置、覆盖）一律先确认。
- 此刻会是空操作的控件渲染为 disabled——一个看起来能点但什么都不做的按钮读起来就是坏了。可用状态依赖数量时，把数量写进标签，让用户看到按钮背后确有工作要做（例如批量操作在标签里写明将作用于多少行）。
- 行默认以只读渲染；显式点「编辑」才展开内联表单。CLI 无法写入的字段（工具注入的环境变量）或不允许手输的字段（picker 托管的路径）渲染为只读文本——绝不做成可编辑输入框。
- 输入控件匹配数据类型：布尔值用两态控件；已知键名用 datalist，数据来自 `mise settings ls --all`。
- 切换版本通过下拉菜单从已安装版本中选择（选中即执行 `mise use`）——绝不自由输入，也不用 datalist：磁盘上不存在的版本无法被提交（issue #132）。当前版本以 `aria-current` 标记并禁用，因为再次选择它是空操作。安装磁盘上还没有的版本归展开行的版本中心负责，不属于切换控件。
- 版本中心（工具页，issue #133）：点击工具名切换行内展开——同一时间只展开一行，触发器不带尖角符号。版本中心有两个子列表。已安装版本：活动版本仅以活动徽标作为唯一活动信号——绝不再配第二个信号（Active 列或「未激活」标注）；非活动版本提供 使用 和 删除此版本，活动版本两者都不提供。可安装版本来自每个（目录，工具）一次缓存的 `mise ls-remote`；已安装的版本仅作标记、不提供操作；其余版本提供 使用（primary——安装并启用）和 仅安装（secondary）。过滤、按版本号降序排序、分页均在客户端完成，数千个版本的列表也保持可用。
- 优先「提交后捕获」，而不是基于缓存/过期状态做提交前校验。已知的 stderr 特征映射为可行动的 i18n 消息——指明对象、说明后果、给出 GUI 内的下一步；mise 原始报错绝不被吞掉——它保留在执行面板的转录里。
- 每个功能在每种布局状态下都可达。收起侧边栏隐藏的是文字标签，不是能力——语言、主题和每个页面都保留图标入口。
- 不留死胡同：任何可浏览的条目都给出顺理成章的下一步。添加工具的入口是工具页顶部的 Registry 搜索（`mise use`，issue #134）；插件页只保留已安装插件的管理（#136 移除了它的 Registry 表——浏览并安装归工具页的搜索负责）。

## 布局与排版

- 长数据绝不在 token 中间断开：固定表格布局 + `nowrap` + `text-overflow: ellipsis` 是唯一默认，且**每个省略单元格 hover 必须能看到完整值**，通过共享的 `Tooltip` primitive 呈现（约 250ms hover 意图延迟，内含复制按钮）；原生 `title` 只保留给短小的图标/按钮标签。承载数据的 flex/grid 单元格加 `min-width: 0`。滚动容器只保留给需要完整浏览的区域（执行日志、文件内容预览）——在正常窗口宽度下，数据表格绝不要求横向滚动来阅读常规列；低于表格声明的 `min-width` 时，由表格自己的滚动器横向滚动，而不是压扁列（issue #90 模式）。（beta 6 后收紧：旧的「省略号或滚动」二选一规则让每个页面各自发挥。）
- 表头与列严格对齐，表头宁可省略号也不溢出进下一列；每个按钮和输入框都位于有标签的表头之下。
- 状态以 `标签: 值 徽章` 单行呈现，徽章紧贴它所修饰的项。不用左右两列、读不出徽章归属的松散网格。
- 中文文案：行尾不留孤字；行内代码片段 `nowrap`。
- 两种语言享有同一套视觉处理——英文是带样式的 banner，中文也得是同一样式的 banner，而不是一句朴素文本。
- 共处同一视觉行的元素必须视觉均衡：任何与 12px 及以上内容同行/同基线的文字，自身渲染不低于 `--size-data`——「安静感」和层级用颜色与字重（`--ice`）表达，绝不用更小的字号表达。`--size-label`（10px）只留给不与正文/数据文字共享基线的独立装饰位：表头、单元格内 chip、空态与加载标签。同一行内成对的控件高度一致；该行需在两种语言下做宽度校验，用 `max-width` + 省略号防御未来更长的字符串。（beta9：从工具栏行规则推广到所有同行场景；工具栏眉签例外和小标签例外一并退役——目标是视觉均衡，字号下限只是它的执行手段。）
- 每个 flex 动作行都要声明对齐方式——不允许裸 `display: flex`、不带 `justify-content` / `margin-left: auto`。页面工具栏约定：提示在左，动作在右。
- 颜色、字号、字距、间距一律取自 token，绝不写字面量——今天恰好等于某个 token 的字面量，就是明天等待发生的漂移。只有书面约定（1px 边框、4px 小元素圆角）豁免，如文件头所述。由 `npm run lint:css-tokens`、`npm run lint:css-font-size`、`npm run lint:css-spacing`、`npm run lint:css-tracking` 四道防线把关。

## 缩窗行为

窗口有最小尺寸；它的职责是防止「不可用」，不是防止「溢出」——内容要自适应。四层各一条规则：

- 窗口：最小尺寸保证布局可用；下游任何层不得指望它来防止挤压。
- 骨架：侧栏保持固定宽（可收起）；工具栏路径省略号；内容区裁切——出现页面级横向滚动条就是 bug（按上面规则由表格自己的滚动器滚动，不算页面级）。
- 内容：表格用固定布局 + 声明列宽；动作列和输入列保持固有宽度不被挤压；长数据遵守上面的省略号规则；散文保留软换行。
- 输入框：每个输入框都要装得下自己的完整 placeholder——提示语被截断是 bug（半个约定教人错误的约定）。

## 操作按钮

一套词汇，四个 variant（色彩/字体语义归 `visual-language.md` 管；用法在这里约束）：

| Variant | 含义 | 例子 |
| --- | --- | --- |
| `primary` | 该行的主行动，且页内无更高优先级竞争 | 运行、安装、添加、保存、选择目录 |
| `secondary` | 常规操作 | 切换、编辑 |
| `danger` | 破坏性 / 敏感 | 卸载、移除 |
| `ghost` | 放弃类或低频 | 取消、在编辑器打开 |

- 一个全局动作只有一个视觉角色：出现在多个表面的动作（如「选择目录」）在全站用同一 variant、同一共享组件渲染。对已有按钮样式做定制复刻是 bug。
- 「选择目录」全站渲染 `primary`——工具栏、空态、表单一律如此（beta9 取代 beta8 的工具栏回落/空态例外条款：同一动作两种呈现读起来像两个不同的按钮，比一个抢眼的按钮更糟）。
- 页面级主按钮一律右对齐（工具栏约定：提示在左、动作在右，用 `justify-content: space-between` 或 `margin-left: auto` 实现），且永远 `size="sm"`；`md` 只保留给非页面工具栏的语境。
- 已知例外，有意为之：执行面板保持等宽字体控件——它是应用的终端语境。不要把它的按钮「统一」到 UI 字体的 Button 上。

## 执行面板

- 面板绝不在命令开始时自动打开。关着就保持关着；开着就保持开着——新命令不许拽走用户正在看的转录。
- 唯一例外：面板关着时命令**失败**，面板自动打开一次。失败只靠状态点太容易漏看。
- 关闭状态下的成功和取消通过 reopen affordance 的状态点呈现。
- 头部顺序：状态 → 复制命令 → 关闭；关闭是和复制同款的文字按钮，绝不用光秃秃的符号。
- 运行锁定（issue #135，经 #138 修订）：一个控件只在它*自己*派发的命令处于运行期间被禁用——锁定是按动作，而非「同一时间最多一条命令」的全局单飞规则，因此多条命令可以并发运行。已加载内容的浏览绝不被锁定：展开/收起行、过滤、排序、分页在长达数分钟的安装过程中都保持可用。打开编辑草稿也不算触发命令——行的「编辑」按钮、草稿的输入框与「取消」在运行期间保持可用，只有表单的「保存」被锁定。常驻表单（添加环境变量、添加设置、添加工具、链接工具）同样如此：输入框与目录选择器保持可用，只有提交（添加 / 使用 / 链接）被锁定。确认对话框是运行感知的：共享的 `ConfirmDialog` 在命令运行期间自行禁用其「确认」按钮（「取消」始终可用），因此仅仅*打开*确认对话框的按钮（移除、卸载、版本级删除、插件卸载）不算触发命令，永不锁定。

## 窗口外壳与主题

- 窗口外壳（标题栏）跟随解析后的主题；要验证，因为它在 Rust 侧配置，不在 CSS 里。
- 浅色与深色是设计出来的对位。一个界面在两种主题下都被*亲眼看过*才算完成。
- 刷新是页面级能力，归顶部工具栏所有：一个全站共享的刷新按钮，接页面注册的刷新动作（invalidate 该页取过的全部数据）。页面和区块内不再各自放刷新按钮（beta8）。

## 文案

- 所有文案走 i18n——字形也不例外：JSX 中禁止硬编码字形字面量；尾随字形走 Button 的 `trailing` prop；菜单/弹层触发器一律不携带 caret 字形。一个 i18n key 对应一个语义角色：同一个词既作状态标签又作动作触发时，用两个 key——标签与动作在各语言里的演化方向不同。用词只出自 `CONTEXT.md`。UI 文案中已退休的词：「上下文/Context」和「项目/project」——说「当前目录」。
- 移除词汇按作用域拆分（ADR-0008）：工具级移除是 卸载 / Unuse，运行 `mise unuse <tool>`——孤立安装则改为 `mise uninstall --all <tool>`，两种情况下确认对话框都展示将执行的确切 argv；版本级文件删除是 删除此版本 / Uninstall（`mise uninstall <tool>@<version>`），且只出现在非活动版本上。绝不允许把「卸载」标签与 `mise uninstall` 配对——那正是 ADR-0008 所退役的 bug。
- 按钮文案绝不以「…」结尾——尾随省略号是已退休的「会打开对话框」旧式惯例；按钮读作纯动词（beta9）。省略号只保留在语义不同的地方：输入框 placeholder 与进行中文案（加载中 / 忙碌态）。由 `npm run lint:i18n-ellipsis` 防线把关。
- 过期版本一律渲染为升级路径：`2026.8.14 → 2026.9.0`，绝不直接贴 CLI 原始输出，绝不只靠颜色表达。
- 弹层和菜单渲染在应用窗口内；绝不用独立 overlay 窗口。

## 字形与图标

- 图标与字形必须大小匹配、风格匹配、颜色匹配。
- 同一个字形在任何地方渲染一致——同一个 span class、同一个 token 颜色；升级路径箭头永远是 `--flare`。
- 菜单/弹层触发器不携带 caret 字形——可展开性由交互表达，而不是靠 `▾` 或 chevron。
- 保留豁免：`›`（分页「Next ›」）和 `←`（返回首页链接）——带标签按钮/链接内的文字字形，继承字号与颜色，允许使用。
- 取代说明：beta4 曾决定语言切换器的 chevron 必须保留作为展开 affordance，该决定已被 beta8 的 caret 移除所取代——不要援引 beta4 恢复 caret。

## 浮层

弹层和菜单——语言切换、目录最近目录菜单，以及今后任何浮层——共用两个 primitive，各司其职：`FloatingMenu` 负责交互式菜单（点击），`Tooltip` 负责非交互的值展示（hover）。这些规则保证它们行为一致；再手写第三种浮层就是 bug。

- 通过 `createPortal` 渲染到 `document.body`——绝不用独立 overlay 窗口（见上文「文案」）。自定义属性声明在 `:root`，所以 body 层级仍能继承主题 token。正是 portal 化，让折叠后的 55px 栏不再裁掉 120px 的语言菜单。
- 位置靠手写：从触发器的 `getBoundingClientRect` 计算；接受 `placement`（`up`/`down`）和对齐参数。不引入定位库——本项目零 UI 库、零定位库。不做超出所请求方向的自动翻转。
- 点击外部以**触发器 ref 与 portal 容器 ref 联合判断**。portal 化后菜单渲染到旧 root 之外；只测旧 root 会把菜单内部的点击误判为「点在外面」而立即关闭。
- z-index 取自 `var(--z-popover)`（60）——高于 `--z-deck`（40），低于 `--z-modal`（100）。绝不在弹层上硬编码 `z-index`；token 是唯一真相来源。
- 遵循 WAI-ARIA 菜单按钮模式：方向键上下在选项间移动，Home/End 跳到首项/末项，Enter/Space 选择（原生按钮激活），Esc 关闭，Tab 关闭并移出焦点。打开时焦点进入首项，关闭时焦点回到触发器（Tab 关闭时除外）。用 `aria-controls` 把触发器和菜单关联；保留 `role="menu"`/`role="menuitem"`、`aria-haspopup="menu"`、`aria-expanded`，并在当前项上保留 `aria-current`。
- 无入场动画。`visual-language.md` 只允许两种环境动效；弹层淡入或滑入是 bug。

## 验收

验收规则归 `docs/agents/conventions.md`（Definition of done / Verification loop）所有——一处一规则，本文档不复述（beta9 归并）。

## 已退休的词汇（硬护栏）

极客 HUD 风已退休（见 visual-language 的 guardrails）。落到行动上：小节标签不带 prompt 符号（`▸`）；只有小节眉签用大写宽字距等宽体——其余标签、正文和数据一律正常大小写；强调靠色彩和字重；菜单触发器不携带 caret 字形（`▾`、chevron SVG；beta8 中移除）。每一处清除都要配上前面的正面表述——目标是 mise 家族的安静气质，不是光秃。
