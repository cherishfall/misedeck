# 执行面板是唯一的 runner —— 读查询同样不例外，不再只管变更操作

> [English](../../../docs/adr/0005-execution-panel-is-the-single-runner-for-reads-too.md)

ADR-0004 让执行面板成为**变更操作**的唯一路径：每次写入都回显真实 argv 并流式输出日志。读查询被允许跳过面板，而其中三个确实跳过了 —— 工具表的 `mise ls --json`，以及两个版本查询的 `mise ls --json <tool>` 和 `mise ls-remote --json <tool>` —— 各自通过自己的 Tauri 命令直达 mise。owner 在版本查询上点了 **Run**，期待面板显示执行了什么，结果什么都没有。这条边界画错了：它围着**危险**画（写入会改变状态，所以要展示），而产品的承诺是围着**可见性**画的（这个 GUI 是用来教 CLI 的，所以什么都要展示）。

**本 ADR 反转这条边界。应用发起的每一次 mise 调用都经由面板的 runner。** 为了做到这一点又不让 mise 执行两次，`run()` 不再返回 `Promise<void>`，而是返回结构化结果；读 hook 把这个结果写入 React Query 缓存，而不再自行取数。因此两个版本查询 hook 干脆没有 query function —— 面板的那次运行**就是**取数本身。

一次运行分为**前台**与**后台**。前台是用户主动要求的一切 —— 变更操作，以及查询区块的 Run 按钮：它占用面板，回显命令，流式输出，并报告退出状态。后台是应用替自己发起的读 —— 工具表的首次加载，以及变更成功后的刷新：同一个 runner、同样的 argv 校验、同样的超时，但它不会打开面板，也不会替换已有的执行记录。这个区分只为一件事存在：变更成功会失效工具列表，若后台刷新也被记录下来，就会在安装刚成功的那一刻把安装日志从用户眼前抽走。

面板同时成为**复制命令**的新家。它本身就是命令历史，这个能力理应在此；DirectoryIndicator 上那个复制按钮 —— 在面板没有命令时只能猜一条出来 —— 被移除。落到剪贴板上的就是回显本身，一条可直接执行的命令行。

## Considered Options

- **让读查询继续留在面板之外，只用页面静态文字回显命令。** 否决 —— 区块提示已经这么做了，owner 依然期待面板有反应。静态文字无法展示退出状态、耗时或 stderr。
- **读查询继续走各自的 Tauri 命令，同时**额外**把它们记进面板。** 否决 —— 通往 mise 有两条路，就有两处需要各自维持 argv、超时和校验的诚实性；而任何「顺便也记一笔」的接缝都在邀请第二次调用。
- **后台刷新也一并记入面板。** 否决 —— 刷新恰好在变更成功时触发，会擦掉用户刚刚换来的日志。一份能被机器覆盖的记录不成其为记录。
- **把复制命令留在目录指示条上。** 否决 —— 在面板之外它没有命令可复制，只能编一条（它会回退成一个裸的 `mise ls`）。面板永远知道真实答案，或者诚实地承认没有。

## Consequences

- `useExecutionContext().run(request, options?)` 返回 `RunCommandResult`；`toJsonResult()` 把一次运行归约为读 hook 缓存的 `JsonResult` 联合类型，并把超时 / 非零退出 / 无法解析的 stdout 映射到错误分支，原样保留 mise 的 stderr。
- 读查询享有与前台运行相同的体验（命令回显、流式输出、退出报告）以及下面的 30 分钟上限。原本「前台命令运行期间禁用一切 Run」的单飞规则是意外引入的全局锁，并非有意为之的后果；issue #138 已用按运行的隔离与按动作的锁定取代它——见「修订」。
- 读查询继承的是流式 runner 的 30 分钟上限，而不是 120 秒的读超时。可以接受：用户能看见这次运行并取消它，而这在静默读查询时代从不成立。
- 切换目录上下文时，已提交的版本查询会被清空，而不是静默重新取数：没有 fetcher 的查询无法重新取数，而一个永远转不完的 loading 就是在撒谎。输入框里的工具名保留，所以针对新目录重跑只需一次点击。
- `tools_ls`、`tools_ls_tool`、`tools_ls_remote` 保留其 Tauri 命令与 runner 函数（类型契约和 Rust 测试不变），但 UI 不再调用它们；前端封装已删除，避免有人无意间把旁路重新引回来。
- 不属于 `ls` 家族的读（`outdated`、`env`、`config ls`、lockfile、任务、插件）仍走各自的命令。它们并非在原则上获得豁免 —— 本 ticket 的范围是 owner 撞上的那三个查询。新增的读面应当经由 runner。

## 修订 —— 单飞是意外引入的全局锁（issue #138）

ADR-0005 原本的后果写道：「读查询同样受面板的单飞规则约束：前台命令运行期间 Run 被禁用。」这个单飞**并非**有意为之的设计后果，而是面板持有一个共享 busy/seq ref 时意外引入的全局锁。它把整个应用的命令都串行化了：发起任意一次前台运行，就会在处处（包括不相关的页面）禁用 Run，以及实际上触发命令的控件。

issue #138 移除了它。runner 不再拒绝或串行化命令。每次 `run()` 都拥有各自隔离的 `RunEntry` 与各自的转录，因此并发的 mise 调用可以共存，日志也绝不会交错。运行锁定改为按动作：一个控件只在它*自己*派发的命令处于运行期间被禁用（通过 `useOwnRun()`），而不是因为别的命令在跑。面板通过一个紧凑的运行切换器呈现并发运行，`ConfirmDialog` 也只在它为之打开的那个命令处于运行期间禁用「确认」。本 ADR 的可见性承诺不变——每一次运行依然回显命令并流式输出——只是那份意外的排他性被去掉了。
