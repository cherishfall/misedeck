# GUI 层能力与「贴合 CLI 的交互」正交

> [English](../../../docs/adr/0007-gui-layer-affordances-are-orthogonal.md)

产品原则 2（「贴合 CLI 的交互」）曾被反复过度套用：agent 援引它来否决 GUI 层的 UX 工作，例如拖拽调整表格列宽、复制路径按钮、安装前检查。所有者在 beta8 反馈（2026-09-08）中纠正了这一误读：MiseDeck 是 GUI，让 GUI 好用的交互能力不是 CLI 功能，也就谈不上违反"禁止发明 CLI 功能"这条禁令。

## Considered Options

- 把原则 2 解读为禁止 mise CLI 没有的任何交互：否决 —— 这会禁掉正常的 GUI 人体工学（调整列宽、复制、悬停态），把产品做成比终端更难用的形态。
- 把原则 2 解读为仅禁止发明的概念/功能（采纳）：贴合 CLI 的约束管的是产品*是什么*；GUI 层管的是它*如何呈现和操作*。

## Decision

「贴合 CLI 的交互」禁令只覆盖**概念、词汇和功能**：MiseDeck 中不得存在 mise CLI 没有对应概念或功能的东西。**呈现层与交互层能力**——表格列宽拖拽、复制到剪贴板按钮、安装前检查、悬停与焦点处理——与 CLI 功能正交，允许且鼓励。一个提案仅当 mise CLI 用户无法预测它会做什么（因为它发明了 mise 没有的东西）时才违反原则 2；"CLI 没有调整列宽的快捷键"不算违反。

## Consequences

- agent 不应再以原则 2 为由否决 GUI 层人体工学 ticket；当这些交互能力服务于同一贴合 CLI 的功能时，还应主动提出。
- 引入 mise 没有的概念、名词或能力的东西，agent 仍应拒绝（或提请所有者决策）——ADR-0004 的词汇禁令和原则 3 完全保持有效。
- AGENTS.md 原则 2 以双语显式写明这一边界。
