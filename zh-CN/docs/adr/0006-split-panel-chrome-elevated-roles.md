# 将 `--panel` 拆分为框架色（侧边栏 / 工具栏 / 执行面板）与抬升表面（弹层 / 对话框 / 横幅 / 面板）两种角色

> [English](../../docs/adr/0006-split-panel-chrome-elevated-roles.md)

在 issue #78 中，三个框架面板——侧边栏、顶工具栏、执行面板——共用同一种扁平表面色（`--hull`），在浅色下显得寡淡、在深色下缺乏层级。修复方案引入了三层*框架*层级（`--hull` → 侧边栏、`--hull-soft` → 工具栏、`--hull-deep` → 执行面板），按角色对位映射自 mise.jdx.dev 的调色板，并把 `--panel` 从 `--hull` 解耦，使抬升表面获得自己的暖色值。本 ADR 记录塑造这次 token 拆分的三个决策，因为每个都难以回退、脱离上下文会令人困惑、且带有真实的取舍。

**决策 1 —— `--panel` 不再是 `--hull` 的别名；它是*抬升*角色，`--hull` 是*框架*角色。** 此决策规避了一个陷阱：`--panel: var(--hull)` 被 11 个组件消费（FloatingMenu、ConfirmDialog、Banner、Panel，以及 Tasks/Doctor/Tools 卡片）。若只重着 `--hull` 来给侧边栏上色，会把每个弹层和对话框一并拖走，使浮起表面从"比页面更亮"变成"比页面更暗"，从而毁掉层级落差。给 `--panel` 独立的暖色字面值（`#F8F0E2` / `#221C1A`）后，11 个抬升消费者自动跟随、零组件改动；只有三个框架表面（侧边栏、工具栏、执行面板）需要显式重接。拆分正是关键所在——框架色与抬升色是不同角色，必须能独立寻址。

**决策 2 —— 深色 `--hull-soft` 偏离 mise 的 `bg-alt`（`#161618`）。** 在 mise 约 50px 的装饰性导航条上，那种近黑看似无形却无妨；MiseDeck 的顶工具栏是约 22px 的*功能性*框架条，必须读作一个可辨的表面。深色值被抬升到 `#1F1816`——处在 `--hull`（`#1C1614`）与 `--hull-deep`（`#261E1A`）之间的暖色过渡——仍留在暖炭黑家族内，不引入新色相。浅色值遵循 mise 的 `bg-alt` 角色。

**决策 3 —— `--panel` 不取 mise 的 `bg-elv` 精确值。** mise 的浅色 `#FFFFFF` 是中性白（偏离暖家族），深色 `#202127` 是蓝灰（蓝 39 > 红 32，偏离品牌）。取而代之，`--panel` 使用两个主题下都落在 `--void` 与 `--hull` *之间*的暖色值——浅色比页面低约 2.4%、比侧边栏高约 1.3%；深色比侧边栏高约 21%、比执行面板低约 14%。这一间隙使被抬起的表面既不同于页面、也不同于框架色；抬升本身仍由既有投影负责，颜色只承载识别。

## 考虑过的选项

- **重着 `--hull` 而保留 `--panel` 为别名。** 否决——会悄悄把每个弹层/对话框/横幅从浮起翻转为沉入，摧毁层级落差（决策 1）。
- **放弃框架层级，只重着抬升表面。** 否决——负责人明确要求三个框架面板不再扁平且雷同；只重着抬升色等于没解决被报告的问题。
- **深色工具栏直接使用 mise 的 `bg-alt`（`#161618`）。** 否决——在 22px 功能条高度下不可见；上游值是为约 50px 装饰条调校的（决策 2）。
- **把 mise 的 `--vp-c-bg-elv`（`#FFFFFF` / `#202127`）照搬给 `--panel`。** 否决——中性白与蓝灰都不合品牌；落在家族内的"之间"暖色值方能在保持识别的同时不脱离家族（决策 3）。

## 后果

- `--hull` 仅作框架色（侧边栏）；`--hull-soft`（工具栏）与 `--hull-deep`（执行面板）是新增框架 token，全部在暖羊皮纸 / 暖炭黑家族内。
- `--panel` 仅作抬升色，两个主题下各有独立暖色字面值；11 个抬升消费者无需改动，仍保持"浮起"。
- `color-mix(var(--hull) N%, transparent)` 着色（约 15 处：Button、Table、Banner、导航 hover、执行面板日志）自动跟随新的 hull 色——预期行为，非回归。
- 无圆角、投影、玻璃拟态或渐变改动；`--void`、`--beam`、`--line`、`--ice`、`--flare`、`--breach`、`--grove`、`--text`、`--dim` 均不动。
- `lint:css-tokens` 是守卫：每个被引用的 token 都必须有定义，因此两个新 token 必须存在，组件方可引用。
