# 国际化（i18n）

> [English](../../../docs/agents/i18n.md)

MiseDeck 如何同时提供英语和简体中文，以及如何在不破坏这一承诺的前提下新增字符串。

## 技术栈（已规定）

- **`react-i18next`**，在 `src/i18n/index.ts` 中初始化。
- 资源文件位于 `src/i18n/en.json` 和 `src/i18n/zh-CN.json`。
- 应用中每个键的类型化目录位于 `src/i18n/keys.ts`。
- 语言提供者位于 `src/i18n/useLanguage.tsx`，对外暴露
  `language` 和 `setLanguage`，将选择持久化在
  `localStorage("misedeck.language")`，变更时重新渲染消费者。
- 可复用的语言切换器位于 `src/components/LanguageSwitcher/`。

## 命名规范 —— 按区域分组的扁平 ID

键是点分路径，按功能区域分组。一级段对应应用中的一个目录（如果还没有对应目录，则对应一个逻辑分组）。在新增分组前先使用已有的：

| 分组         | 用途                                                |
| ------------ | --------------------------------------------------- |
| `app`        | 全局身份标识（wordmark、tagline）                   |
| `common`     | 跨页面复用的通用动词（ok、cancel…）                 |
| `nav`        | 区段标签，即便导航还没上线（#23）                   |
| `starter`    | starter 页面（已有）                                |
| `states`     | 任何页面上的状态/错误视图                           |
| `labels`     | 数据展示中的字段标签                                |
| `errors`     | `conventions.md` 中固定的错误码                     |
| `languages`  | 语言切换器自身的 UI 文案                            |

约定：

- 段内使用 **小驼峰**（`commandFailed`，而不是 `command_failed`）。
- `common.*` 中 **动词优先，名词在后**（例如 `search` 排在 `results`
  之前）；其他分组名词优先。
- **不要加位置或页面相关的前缀** —— 按区域分组而非按页面分组，
  这样在页面间迁移的标签可以保留其键。

## 如何新增一个字符串

三步，全部在同一次提交中完成：

1. **新增常量**到 `src/i18n/keys.ts` 中对应的分组
   （例如 `common.retry: "common.retry"`）。
2. **新增同样的路径**到 `src/i18n/en.json` 和
   `src/i18n/zh-CN.json` **两个文件**。相同的路径、相同的嵌套、
   相同的缩进。英文文案是语气上的权威；中文文案可以忠实翻译或
   本地化改写，但绝不能留空。
3. **使用该常量**作为调用点：
   ```tsx
   <button>{t(I18N_KEYS.common.retry)}</button>
   ```
   始终走 `I18N_KEYS` —— 绝不打字字符串字面量 —— 这样编译器可以
   在目录中捕获拼写错误。

然后运行守门脚本：

```bash
npm run lint:i18n
```

它必须以 0 退出码退出。如果不是，说明两个资源文件不同步
（见下面的"为什么每个键必须同时存在于两个文件"）。

## 为什么每个键必须同时存在于两个文件（在同一次提交中）

一个键存在于 `en.json` 但缺失于 `zh-CN.json` 意味着中文 UI 会静默
回退到英文文案。更糟的是，一个键存在于 `zh-CN.json` 但缺失于
`en.json` 意味着英文 fallback 本身也缺失，用户将看到原始的点分
路径。这两种都是 bug，我们希望它们在构建时被发现，而不是在用户
眼前被发现。

`scripts/check-i18n.ts` 遍历两棵 JSON 树，分别计算它们的叶子键
集合，如果不一致则以清晰的 diff 非零退出。该脚本被接入
`npm run lint:i18n` 和 `npm run ci` 聚合命令。**CI 红意味着有键
只落在了一个文件里。** 修复方法是补齐缺失的翻译（或删除未使用
的键），不是禁用这个检查。

## 语言如何被选择

检测链路按优先级顺序：

1. **`localStorage("misedeck.language")`** —— 用户在
   `<LanguageSwitcher>` 中显式选择语言时设置。跨重启保留；
   覆盖下面所有项。
2. **浏览器语言**（`navigator.language`）—— 操作系统偏好，
   首次运行由 `i18next-browser-languagedetector` 解析。
   中文区域浏览器以 `zh-CN` 启动；其他以 `en` 启动。
3. **Fallback** —— `src/i18n/index.ts` 中的 `fallbackLng: "en"`。
   上述都没有匹配时，UI 显示英文。

提供者会在每次 `languageChanged` 事件上重新渲染，因此切换切换器
会更新所有可见文案而无需重新加载页面。

## 错误码存放在哪里

`docs/agents/conventions.md` 钉住了一组固定的 `AppError.code` 取值：

```
MISE_NOT_FOUND  MISE_TOO_OLD  COMMAND_FAILED  PARSE_FAILED  UNTRUSTED  TIMEOUT
```

每个都在 `errors.*` 下有对应的键：

- `errors.miseNotFound`
- `errors.miseTooOld`
- `errors.timeout`
- `errors.generic`
- `errors.network`
- `errors.untrusted`
- `errors.unknown`（尚未分类的 code 的兜底）

UI 对 `code` 做模式匹配（见 `conventions.md`），然后调用
`t(I18N_KEYS.errors.<code-camelCase>)` 获取人类可读文案。
发明新错误码是有意识的 API 变更 —— 提一个 issue、更新本文档、
在两个资源文件中新增键，并在同一次改动中扩展
`misedeck/src/types/tauri.ts` 和 `misedeck/src-tauri/src/mise.rs`。

## 新增一种语言

`src/i18n/useLanguage.tsx` 中的 `SUPPORTED_LANGUAGES` 是一个
`const` 元组 —— 若要新增第三种语言：

1. 把 BCP-47 代码（例如 `"ja"`）追加到该元组，并追加到
   `src/i18n/index.ts` 中的 `supportedLngs`。
2. 在现有两个文件旁新增一个 `src/i18n/<code>.json`。
3. 更新 `I18N_KEYS.languages` 的展示标签，并把新选项加入
   `useLanguage.tsx` 中的 `LANGUAGE_LABELS`。
4. 把每个已有键翻译进新文件（`lint:i18n` 脚本会在达到对等之前
   拒绝通过）。
