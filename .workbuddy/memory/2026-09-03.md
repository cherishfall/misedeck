## 修 CI 红灯（非 beta.5 引入）

- 现象：ci.yml 在 ubuntu-latest 的 `cargo test` 上红，`tests/terminal.rs::open_in_terminal_rejects_empty_path` 断言 COMMAND_FAILED，实际得到 TERMINAL_NOT_FOUND。最早可追溯到 5c3ee3f（#54 时期），早于本会话所有改动；macOS/Windows 全绿，release.yml 安装包构建始终成功。
- 根因：空路径按设计退化到 `$HOME`（shell.rs:410-429），Linux runner 上没有终端模拟器时返回已文档化的 TERMINAL_NOT_FOUND（同文件另一个测试就是断言这个码），测试断言过严——是测试的错，不是实现的错。
- 修复：断言放宽为 COMMAND_FAILED 或 TERMINAL_NOT_FOUND，注释说明两种合法的失败路径（2463528）；本地 `cargo test --test terminal` 5/5 通过，CI 已转绿。
- 教训：跨平台的集成测试断言要考虑"环境无依赖程序"这一分支；只接受一种错误码会让 Linux CI 长期红灯。
- 处置：修复仅测试代码，不影响已构建产物，故 v1.0.0-beta.5 标签保持原样，修复顺延到 beta.6（重打已发布 tag 是对外破坏性操作，需用户拍板）。

**Issue 5【bug】已安装版本有数据却显示空**
- 根因：`mise ls --json <tool>` 返回**数组**，而 `parseLsPayload`（`miseTools.ts:73-76`）只接受**对象**、遇数组直接 `return []` → `rows.length === 0` → 空状态。
- 对比：顶部「已安装工具」表走 `mise ls --json`（无 tool 参数，返回对象）所以正常。同一 parser 两种 payload 形状。
- 修复纯前端（Rust argv 正确）；**要补 Rust 测试**——`src-tauri/tests/tools.rs` 完全没覆盖 `mise_ls_tool`。
- 排除的假设：`(symlink)` 后缀不是原因——`--json` 模式下 version 字段干净，symlink 信息在独立字段。

**Issue 6【需求】版本查询分页**（覆盖 installed + remote 两个区块）
- 现状：`foldLimit=10` hardcoded，点「显示全部 3181 项」后**一次性渲染 3181 行** DOM。
- **关键约束：`mise ls` / `mise ls-remote` 都不支持 `--limit`/`--offset`**，分页只能客户端切片。
- 项目无任何分页组件，需新建 `Pagination`。
- 定稿：去掉「显示全部 N 项」；≤10 行不分页（阈值切换）；pageSize 纯输入**最小 10**；分页器 = 上一页 / 第 X/Y 页·共 N 条 / 下一页 / 跳转。
- 该方案**取代** beta4 #55 的「折叠为展开全部」决策，`ui-ux-rules.md:21` 需同步改（含 zh-CN 镜像）。

**Issue 7【需求】已安装版本加卸载按钮 → 与 Issue 6 合并同一 ticket**

**Issue 8【需求】新增「链接工具」区块（mise link）**
- **`mise link` 实测语义**（本机 mise 2026.8.14）：`mise link [-f --force] <TOOL@VERSION> <PATH>`——**tool@version 在前、path 在后**；唯一标志 `--force`；**`mise unlink` 不存在**，移除走 `mise uninstall <tool>@<version>`。
- **命名受 ADR-0004 硬约束**：mise 自己的动词就是 `link`，唯一安全名是 **Link / 链接工具**（禁用注册/绑定/挂载/关联）。
- 定稿：位置=安装工具之后、已安装版本之前；**不暴露 --force**，冲突时给提示（提交后捕获 stderr 匹配 `already exists`，**原始错误始终保留在执行面板**——数据诚实原则）。
- 冲突提示文案（我优化过）：`{tool}@{version} 已存在，无法重复链接。请先卸载该版本，再重新链接。`

**可复用架构模式（重要）**：
- **工具变更命令无需新增 Tauri command**——都走通用 `run_mise_command`（`lib.rs:229-296`），argv 由**前端**构造。模式：Rust 侧纯 argv 构造器（`mise.rs`）+ `tests/tool_mutations.rs` 断言 + JS 副本（`ToolsPage.tsx` 的 `miseInstallArgs`/`miseUninstallArgs`/…）。
- 新变更操作复用 `runMutation`（`ToolsPage.tsx:282-289`）→ **自动继承信任门 + 单并发保护**。
- 目录选择原语已存在：`openDialog({ directory: true })` from `@tauri-apps/plugin-dialog`（`DirectoryIndicator.tsx:85-98`）。注意它默认写全局目录上下文，局部用途需单独存 state。

## 【重要】流式输出被截断的竞态 bug（1feb11d，beta.6 发布后发现）

**发现路径**：发完 beta.6 后一个**只改了 HANDOFF.md** 的提交把 CI 跑红了 → `install::tests::run_install_streams_a_short_command` 期望 `["line-1","line-2"]` 实得 `[]`。文档提交不可能影响 Rust 测试 → 判定 flaky → 但追下去发现是**生产 bug**，不是断言过严。

**根因（通用模式，值得记住）**：两个流式 runner（`mise.rs` 主流式器、`install.rs` 的 `run_install`）都是「每个管道一个读线程 → `mpsc` channel → 主线程轮询 `child.try_wait()`」。退出分支里写成：

```rust
Ok(Some(status)) => {
    while let Ok(line) = out_rx.try_recv() { ... }  // 先抽干
    let _ = out_thread.join();                       // 后 join  ← 错
}
```

`try_wait()` 观测到退出的那一刻，读线程可能还没把管道里的行发出来 → 抽干时 channel 是空的 → `join()` 之后又没人再抽 → **这些行永久丢失**。开发机/macOS 上读线程通常抢先所以复现不了；Linux runner 负载高时必现。

**正确顺序：先 join 再抽干**。`join()` 后生产者一定结束、所有行都在 channel 里，此时抽干是确定的。子进程已退出 → 管道 EOF → `join()` 必然返回，**不会死锁**。

**四个站点都要改**：`mise.rs` 退出分支 + 超时分支；`install.rs` 的 `run_install` 退出分支 + 超时分支（超时分支是 `kill→wait→join` 但 join 后没抽干，kill 前最后几行同样丢）。测试 `run_install_streams_a_short_command` 内联复刻了同一套循环，也要改。

**为什么严重**：`mise.rs` 是 ADR-0005 之后**所有** mise 调用的必经之路，末尾输出（尤其是报错行）被静默截断 = 违反数据诚实原则，用户会看到「命令失败但错误信息为空」。

**教训**：
1. **CI 红灯即使是文档提交也要追到底** —— 这次就是靠"文档不该影响测试"这个矛盾顺藤摸瓜挖出生产 bug 的。别直接 rerun 了事。
2. 「测试 flaky」和「生产有竞态」常常是同一件事，先怀疑后者。
3. 发版后发现影响产物的 bug，**重打 tag 属对外操作**（要删远程 tag + release），按 AGENTS.md 必须停下来问用户，不能自主决定。
4. **用户本次选择：不动 beta.6，修复顺延下次发版。** 已写进 HANDOFF 生效，下个会话别再拿这事来问、也别自作主张重打。已知后果要记住：beta.6 的产物存在「命令失败但错误信息为空」的可能，若用户反馈该现象就是这个 bug（master 已修）。
