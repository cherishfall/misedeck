# Internationalization (i18n)

> [简体中文](../../zh-CN/docs/agents/i18n.md)

How MiseDeck ships English and Simplified Chinese side by side, and how to
add a new string without breaking that promise.

## Stack (prescribed)

- **`react-i18next`** initialized in `src/i18n/index.ts`.
- Resource files at `src/i18n/en.json` and `src/i18n/zh-CN.json`.
- A typed catalog of every key the app uses at `src/i18n/keys.ts`.
- A language provider at `src/i18n/useLanguage.tsx` that exposes
  `language` and `setLanguage`, persists the choice in
  `localStorage("misedeck.language")`, and re-renders consumers on change.
- A reusable switcher at `src/components/LanguageSwitcher/`.

## Naming convention — flat IDs grouped by area

Keys are dotted paths, grouped by feature area. The top-level segment
mirrors a folder in the app (or a logical group if no folder yet). Use
the existing groups before inventing a new one:

| Group       | Holds                                            |
| ----------- | ------------------------------------------------ |
| `app`       | App-wide identity (wordmark, tagline)            |
| `common`    | Generic verbs reused across pages (ok, cancel…)  |
| `nav`       | Section labels, even before the nav ships (#23)  |
| `starter`   | The starter page (existing)                      |
| `states`    | Status / error views on any page                 |
| `labels`    | Field labels in data displays                    |
| `errors`    | Fixed error codes from `conventions.md`          |
| `languages` | UI strings for the language switcher itself      |

Conventions:

- **Lower camelCase** within a segment (`commandFailed`, not `command_failed`).
- **Verbs first, nouns second** in `common.*` (e.g. `search` before
  `results`); nouns first elsewhere.
- **No positional or page-specific prefixes** — group by area, not by
  page, so a label that moves between pages keeps its key.

## How to add a new string

Three steps, all in the same commit:

1. **Add the constant** to `src/i18n/keys.ts` in the right group
   (e.g. `common.retry: "common.retry"`).
2. **Add the same path** to **both** `src/i18n/en.json` and
   `src/i18n/zh-CN.json`. Same path, same nesting, same indentation.
   The English copy is the source of truth for tone; the Chinese copy
   may be a faithful translation or a localized rewrite, but never an
   empty string.
3. **Use the constant** at the call site:
   ```tsx
   <button>{t(I18N_KEYS.common.retry)}</button>
   ```
   Always go through `I18N_KEYS` — never type a string literal — so
   the compiler catches typos in the catalog.

Then run the guard:

```bash
npm run lint:i18n
```

It must exit zero. If it doesn't, the two resource files are out of
sync (see "Why every key MUST be in both files" below).

## Why every key MUST be in both files (in the same commit)

A key present in `en.json` but missing from `zh-CN.json` means the
Chinese UI would silently fall back to the English copy. Worse, a
key in `zh-CN.json` but missing from `en.json` means the English
fallback itself is missing, so the user sees a raw dotted path. Both
are bugs we want to catch at build time, not at the user's eye.

`scripts/check-i18n.ts` walks both JSON trees, computes the leaf-key
set for each, and exits non-zero with a clear diff if they differ.
The script is wired into `npm run lint:i18n` and the `npm run ci`
aggregate. **CI red means a key landed in only one file.** The fix is
to add the missing translation (or remove the unused key), not to
disable the check.

## How the language is chosen

The detection chain, in order of precedence:

1. **`localStorage("misedeck.language")`** — set by
   `<LanguageSwitcher>` when the user picks a language explicitly.
   Survives a relaunch; overrides everything below.
2. **Browser language** (`navigator.language`) — the OS preference,
   resolved by `i18next-browser-languagedetector` on first run. A
   Chinese-locale browser starts in `zh-CN`; everything else starts
   in `en`.
3. **Fallback** — `fallbackLng: "en"` in `src/i18n/index.ts`. If
   nothing above matches, the UI is English.

The provider re-renders on every `languageChanged` event, so toggling
the switcher updates all visible copy without a page reload.

## Where the error codes live

`docs/agents/conventions.md` pins a fixed set of `AppError.code`
values:

```
MISE_NOT_FOUND  MISE_TOO_OLD  COMMAND_FAILED  PARSE_FAILED  UNTRUSTED  TIMEOUT
```

Each has a matching key in `errors.*`:

- `errors.miseNotFound`
- `errors.miseTooOld`
- `errors.timeout`
- `errors.generic`
- `errors.network`
- `errors.untrusted`
- `errors.unknown` (catch-all for codes we haven't catalogued yet)

The UI pattern-matches on the `code` (see `conventions.md`), then
calls `t(I18N_KEYS.errors.<code-camelCase>)` for the human copy.
Inventing a new error code is a deliberate API change — open an
issue, update this doc, add the key to both resource files, and
extend `misedeck/src/types/tauri.ts` and
`misedeck/src-tauri/src/mise.rs` in the same change.

## Adding a new language

`SUPPORTED_LANGUAGES` in `src/i18n/useLanguage.tsx` is a `const`
tuple — to add a third language:

1. Append the BCP-47 code (e.g. `"ja"`) to the tuple and to
   `supportedLngs` in `src/i18n/index.ts`.
2. Drop a new `src/i18n/<code>.json` next to the existing pair.
3. Update `I18N_KEYS.languages` with the display label and add the
   option to `LANGUAGE_LABELS` in `useLanguage.tsx`.
4. Translate every existing key into the new file (the `lint:i18n`
   script will refuse to pass until parity is achieved).
