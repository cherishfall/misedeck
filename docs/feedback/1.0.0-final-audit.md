## Method

- Four read-only static passes: frontend/UI, Rust/backend + cross-platform, docs/release, features/mise semantics.
- Runtime simulation via a headless-Chrome CDP harness with a mocked Tauri IPC layer: all 8 pages × en/zh × light/dark at 1200×720 and 900×600, dialogs, inline editors, keyboard focus, malformed payloads, missing/old mise, hangs.

## P0

### R-0 (issue #266) — v1.0.0's public release body is a commit message, not the curated template

`release.yml` treats any non-empty `git tag -l --format='%(contents)'` as an annotated-tag message. For a lightweight tag, that format returns the **commit message**, so the template fallback is dead. Verified:

```
git cat-file -t v1.0.0                    → commit
git tag -l --format='%(contents)' v1.0.0  → chore(release): cut 1.0.0 (#252) …
gh release view v1.0.0 --json body        → the same commit message
```

Impact: the GA release page has no install steps, Gatekeeper/SmartScreen guidance, or SHA256SUMS verification. `HANDOFF.md:9` currently claims the template supplied the body — false. The template fallback also has two latent bugs: `<version>` substitution renders `MiseDeck_v1.0.0_x64-setup.exe` (asset is `MiseDeck_1.0.0_x64-setup.exe`), and relative links (`../README.md`, `../docs/adr/…`) 404 on `/releases/tag/`.

Fix: gate `%(contents)` on `git cat-file -t "$TAG" = tag`; strip the leading `v`; use absolute URLs; correct `ci.md` and `HANDOFF.md`. Correcting the published body is an owner-gated outward action.

## P1

### U-1 (issue #267) — Editing a task through the inline form silently wipes fields

`TaskForm` carries only description / depends / run, then dispatches `mise tasks add`. That command replaces the whole `[tasks.<name>]` table. Real probe:

```
before: description, alias="b", dir="sub", shell="bash",
        sources=["src/**"], outputs=["dist/**"], run_windows="echo win"
$ mise tasks add build -- echo new
after:  [tasks.build] run = "echo new"   # every other field gone
```

`mise tasks add` supports `--alias`, `--dir`, `--shell`, `--sources`, `--outputs`, `--run-windows`, `--hide`, `--quiet`, `--silent`, `--raw`, `--depends-post`, `--wait-for`; the app forwards none of them. The source comment claiming the form writes "the same fields" is false.

Fix: either forward every supported flag from the form, or gate inline Edit when the task has fields the form cannot round-trip; the safe terminal is "Open in editor" for those tasks.

### U-2 (issue #267) — Editing a task defined outside the write target creates a shadow copy

`mise tasks add` writes to the nearest project config and has no `--global`. Editing a task from the global config (or a parent config) creates a new table in the nearest project config; the original is unchanged and the new table shadows it. Real probe:

```
$ HOME=/tmp/audit6 mise tasks add foo -- echo new
/tmp/audit6/mise.toml: [tasks.foo] run = "echo new"
# the original global config still says run = "echo global"
```

Fix: compute the write target and allow inline Edit only when `task.source` is a config directly in the active directory; otherwise show "Open in editor" (or edit the defining file explicitly).

### E-1 (issue #268) — Unset/rename of a parent-config env var reports success but changes nothing

`isEnvWriteScopeMismatch` only distinguishes global vs non-global. A var defined in a parent `mise.toml` is labelled "Current directory" and is considered in scope. Real probe:

```
$ cd proj/sub && mise env --json-extended | jq .FOO
{ "source": ".../proj/mise.toml", "value": "parent" }
$ mise unset FOO           # exit 0
$ cat mise.toml            # [tools] … [env]   (empty table added)
$ mise env --json | jq .FOO
"parent"                   # still active
```

Rename compounds it: unset-old runs first (no-op), then set-new creates a shadow, so both keys remain. A failed set-new after unset-old can lose the old value.

Fix: treat any source outside the active directory as out of scope; disable Unset for it (with the existing reason tooltip) or pass the defining file; reorder rename to set-new then unset-old so a failure cannot destroy the old value.

### E-2 (issue #268) — Trust status can report the parent config's trust as the directory's

`mise trust --show` lists the trusted parent first and the untrusted child second. `mise.rs:1266` returns on the first line containing `trusted`, so the app reports "trusted" for a directory whose own config is untrusted. Real probe:

```
$ mise trust --show
/proj: trusted
/proj/sub: untrusted
```

Reads currently still ran in this mise version, so the confirmed defect is the status/indicator lie (plus the trust gate not firing), not an established RCE. Fix: select the line for the resolved cwd (or the longest applicable path), and treat any applicable untrusted line as untrusted.

### T-1 (issue #269) — A requested-but-missing tool is shown as active, with a same-version "upgrade"

Real probe for `[tools] node = "22.0.0"` with another version installed:

```
mise ls --json      → {"version":"22.0.0","requested_version":"22.0.0","installed":false,"active":false}
mise outdated --json → {"requested":"22.0.0","current":null,"latest":"22.0.0"}
```

`ToolsPage.tsx:337` picks `active ?? items[0]`, ignores `installed`, and `versions.ts:99-101` treats `current: null` as an upgrade target. The row reads `22.0.0` with "Upgrade available · 22.0.0" and is counted as outdated.

Fix: prefer active → newest installed → missing request; render a "not installed" badge; require a non-null current for an upgrade chip/count.

### D-1 (issue #270) — Wrong-shaped JSON renders as empty/healthy instead of an error

`parse*` payloads coerce an unexpected top-level shape to `[]` or `{}`. Simulation (valid JSON, wrong shape) confirms:

| Page | Mocked wrong shape | Rendered |
| --- | --- | --- |
| Env | object not matching extended entries | "No env vars" |
| Tasks | object instead of array | "No tasks" |
| Settings | wrong shape | "No settings are explicitly set" |
| Plugins | wrong shape | "No plugins installed" |
| Preview | wrong shape | "No config files" (lockfile still shown) |
| Doctor | wrong shape | **green "Status: OK", "Shell activation: Activated"** |

The Doctor case is the worst: an unusable report is presented as a clean bill of health. Separately, a genuine `PARSE_FAILED` (unparsable stdout) renders "did not return and wrote no stderr" — false for a command that returned garbage — because the error cards ignore `err.message`.

Fix: validate the expected top-level shape in the read layer and surface `PARSE_FAILED`; branch error copy on `err.code` and render the parse detail.

### L-1 (issue #271) — Tasks/Settings break at the supported 900×600 minimum; Tasks clips at 1200×720

Measured with the app's own min window size:

- **1200×720 /tasks**: table client 952, scroll width 983; each "Open in editor" button's right edge is 1205 (> viewport 1200). Horizontal scroll is the only way to reach the third action.
- **900×600 /tasks**: description column collapses to 0 px (header invisible, body 1 char wide), Run/Edit/Open in editor are at x 863–1093 (> 900).
- **900×600 /settings**: Value column collapses to 0 px (header and values invisible).
- **900×600 /tools and /env**: fixed min-width exceeds the 652 px content area; actions sit beyond the viewport and require inner horizontal scrolling. Lower severity than the zero-width columns, same family.

Fix: make the actions column wide enough for its contents, and give Description/Value a minimum width so the table scrolls rather than collapsing a column; verify at 900 and 1200.

### K-1 (issue #272) — Escape inside a nested overwrite/flatten dialog clears the draft behind it

Env "Add", Settings "Add", and the Tasks create/edit form wrap their inputs and `ConfirmDialog` in `KeyForm`. `KeyForm` stops Escape at the form; `ConfirmDialog` listens on `window` (bubble), so its Escape never runs. Visual simulation with an existing `NODE_ENV`:

1. Type name `NODE_ENV`, value `overwrite`, click Add → overwrite dialog opens.
2. Press Escape → dialog **stays open**, but the name/value behind it are cleared.
3. Dialog now reads "Overwrite ?" and the command becomes `mise set -g =`; Add is enabled.

In the Tasks form the same keypress cancels the entire editor and discards every unsaved field.

Fix: run `ConfirmDialog`'s key handling in the capture phase (or ignore Escape in `KeyForm` when the target is inside an open modal), plus a keyboard regression test.

## P2

### K-2 (issue #280) — Registry combobox keyboard selection can move off-screen
Arrow keys change `activeIndex` but never scroll the active option into the 280 px list; Enter can pick an invisible item. `AddToolSection.tsx:915-947`, `AddToolSection.module.css:248-259`.

### K-3 (issue #280) — Settings count ignores the active filter
With a filter active the hint still says "40 settings" while 3 rows render; filtered zero never reads "0 of 40". `SettingsPage.tsx:190-194,316`. Tasks already has the correct pattern.

### K-4 (issue #280) — Pagination Jump is enabled when it would no-op
Empty/invalid value → active-looking Jump and Enter do nothing. `Pagination.tsx:68-75,132-153`.

### K-5 (issue #280) — Scrollable config/lockfile `<pre>` blocks are not keyboard-focusable
Capped at 480 px with `overflow:auto`, but no tab stop, so keyboard users cannot scroll clipped content. `DirectoryPreview.tsx:536,648`; `DirectoryPreview.module.css:196-209`. WKWebView/WebKitGTK behavior should be verified on a real build.

### T-2 (issue #269) — Toolbar Refresh cannot refresh Manage versions' remote list
Refresh invalidates ls/outdated/trust/registry, but the `ls-remote` query is populated by `readIntoCache` and its dispatch effect returns early while cached data exists. A newly released version stays invisible for the session. `ToolsPage.tsx:267-278`; `useToolsList.ts:145-152`; `AddToolSection.tsx:193-201`.

### S-1 (issue #273) — Settings "Show all (--all)" is a dead control in Directory mode
`settingsLsArgs` always adds `--local` when `cwd !== null`; `mise settings ls --all --local` returns only explicitly-set local keys (`{}` in the probe, vs 117 with `--all` alone). The toggle adds no rows and leaves add-form suggestions empty. `useIssue29.ts:38-42,61`; `SettingsPage.tsx:115-116,330-338,412`.

### O-1 (issue #274) — Overview labels a parent project config as "Global"
`DirectoryPreview.tsx:106-112` maps `!isPathUnder(cwd, source)` to `global`. A tool from a parent `mise.toml` is therefore shown as "Global". Use `isGlobalConfigPath` and add a parent/ancestor label; the same distinction affects the Env "Current directory" badge.

### O-2 — Global Overview hides resolved tools (owner decision)
`DirectoryPreview.tsx:214-218` returns no tool rows in Global mode and shows "Choose directory", although `mise -C $HOME ls --json` resolves global tools. This may be deliberate; if so, document the exception in product-logic.

### P-1 (issue #275) — Plugin `ref`/`sha` are parsed but never displayed
`types/tauri.ts:339-351` and `parsePlugins` keep ref/commit; the table renders only name/source/actions. Users cannot see which ref/commit a plugin uses.

### A-1 (issue #276) — Tools/Settings reads bypass `MISE_SAFE`, contradicting the architecture
`useToolsList.ts:54-63,106` (`mise ls --json`) and `useIssue29.ts:51-61` (`settings ls --json-extended`) call the panel runner → `run_mise_command` → `run_mise_tracked`, which passes `safe_mode=false`. `docs/agents/architecture.md:21` says every read funnels through `run_mise_json` with `MISE_SAFE=1`. `TasksPage.tsx:269-273` also claims a task run gets `MISE_SAFE=1`; it does not. Defense-in-depth loss + contract drift.

### R-1 (issue #277) — Unbounded output buffering in streaming runners
`spawn_line_reader` uses unbounded `read_until` and an unbounded channel; `drain_streams` appends every line to `stdout_buf`/`stderr_buf`; `run_mise_command` returns the whole outcome over IPC after streaming each line. A newline-free line or a 30-minute chatty task grows memory without bound. Same pattern in `install.rs:169-178`. Add per-line/aggregate caps and a truncation notice.

### R-2 (issue #277) — Windows shell detection is effectively always PowerShell
`shell.rs:161-169` returns PowerShell when `pwsh.exe` or `powershell.exe` exists. Windows PowerShell 5.1 is effectively always present, so the documented Git Bash fallback is unreachable and those users get PowerShell activation instructions. `which_exists` spawns the bare name `pwsh.exe` (binary-planting surface); other Windows binaries were System32-qualified in #253. Check `$SHELL` first, probe with an absolute path/`where.exe`, add Windows tests.

### R-3 (issue #278) — Release/CI hardening gaps
`release.yml:21-22` grants `contents: write` to every job (including build legs running `npm ci`/build scripts); actions are pinned to mutable tags. `cargo clippy --all-targets -- -D warnings` fails with 14 style/`unexpected_cfgs` lints and CI has no clippy/fmt gate. Windows CI runs only `cargo test --lib`, so taskkill/PowerShell-installer/terminal paths have no integration coverage. `tests/runner.rs:134-139` accepts `contains(cwd) || contains("-C")`, which passes even when cwd is wrong. Fix: least-privilege job permissions, SHA pins, add clippy after clearing lints, a Windows-native teardown test, and assert the exact `-C <cwd>`.

### D-2 (issue #279) — GA docs contradiction bundle
- `docs/agents/ci.md:155` + zh: packages are "GPG signed"; they are unsigned (README/template say so).
- `docs/adr/0009-…:9` + `update.rs:19`: "every MiseDeck release is a prerelease" and `releases/latest` "resolves to nothing". v1.0.0 is `isPrerelease:false`, so `latest` resolves. Add a status note; the decision still stands.
- `docs/agents/architecture.md:24`: "`opener:default` is absent because nothing opens a URL"; `ExternalLink` and `external_link.rs:87` do open URLs. Explain the deliberate no-default design instead.
- ADR-0002 / ci.md Gatekeeper: "right-click → Open"; macOS 15 removed that. README already documents xattr / Open Anyway.
- `misedeck/README.md:54-60` still ships the Tauri/Vite scaffold README; zh heading is untranslated.
- Inventory drift: `docs/agents/domain.md:24` tree ends at `src/` (actually `misedeck/src/`); `i18n.md:23-27` omits `failureNotice`; `conventions.md:52` lists 2 test suites (21 exist).
- `ci.md:234` says the workflow consumes English only and can be extended "once #32 lands"; #32 is closed and both READMEs are bilingual.

### D-3 (issue #266, #279) — Release template rendering
Language switcher sits mid-body with `../README.md` links and ADR links are repo-relative; both 404 on the Releases page. zh template title is `MiseDeck v<version>` → `MiseDeck vv1.0.0`.
