# 1.0.0 pre-GA i18n audit（2026-10-21）

> Static audit of the bilingual (English / 简体中文) copy surface, commissioned by the
> product owner as part of the pre-1.0.0-GA release review. No app launch, no build,
> no repo modification beyond this file.
>
> Baseline: master `37d27fb` (1.0.0-beta.17), clean tree.
> Scope: `misedeck/src/i18n/{en.json, zh-CN.json, keys.ts, index.ts, useLanguage.tsx}`,
> plus every call site that renders catalog copy (`appVersionCopy.ts`, `appError.ts`,
> `OutdatedHint`, `QueryHint`, `ActivationBanner`, `HomePage`, `DoctorPage`,
> `DirectoryIndicator`, `AppVersion`, `shell.rs` terminal probe table).
> Vocabulary source of truth: `CONTEXT.md` (+ `zh-CN/CONTEXT.md`); engineering rules:
> `docs/agents/i18n.md`; domain rules: `docs/adr/0004`; copy rules: `docs/design/ui-ux-rules.md` → Copy.

## Verdict summary

- **P0 = 0** — nothing blocks the release.
- **P1 = 4** — two glossary violations where English contradicts the approved term
  (Chinese is already correct in both), one retired Chinese term, and one error message
  that states a fact that stopped being true after beta17 (#245).
- **P2 = 19** — mostly copy-polish; three are owner decisions (loanword vs. translated
  term, untranslated `RAW` label, outdated-hint verb).
- Mechanical health is excellent: all repo guards pass, key/placeholder parity is exact,
  plural forms are complete, interpolation is safe. The debt is in *wording*, not plumbing.

## Audited clean (checked, no findings)

These classes were verified and need no rework:

- **Repo guard suite** — all green from a clean tree:
  - `npx tsx scripts/check-i18n.ts` → exit 0:
    `i18n parity OK — 442 leaf key(s) identical across en.json and zh-CN.json.`
    `i18n call-site scan OK — every t('...') literal is a known key.`
    `i18n interpolation OK — 492 t(I18N_KEYS…) call site(s) match their {{placeholders}} in en + zh-CN.`
    `i18n dead-key check OK — all 442 leaf key(s) are referenced.`
    `i18n copy check OK — no Markdown backticks across 884 catalog string(s).`
  - `check-i18n-concat.ts` → OK (no `t(...)` joined with `+` or embedded in template literals).
  - `check-i18n-ellipsis.ts` → OK (no button label ends in "…").
  - The other eight `check-*.ts` scripts (command-hint, install-echo-parity, modal-focus,
    nested-interactive, page-layout, css-tokens/font-size/spacing/tracking) → all OK.
- **Independent re-verification** (my own script, not the repo's): key sets identical in
  both catalogs; `{{placeholder}}` sets identical per key in both catalogs; zero
  single-brace literals (no i18next interpolation hazards); zero empty values; both
  files parse as strict JSON.
- **Plural forms** — all four count keys carry `_one` in both catalogs
  (`common.outdatedCount`, `tasks.count`, `tasks.countFiltered`, `settings.count`).
  English one/other is correct CLDR; Chinese has no plural, so zh `_one` is
  parity-required and identical to the base (i18next's zh plural resolver only selects
  the base form — the zh `_one` keys are never rendered, which is correct behavior, not
  dead weight). `tools.queries.pagination.total` ("{{count}} total") and
  `execution.runsRunning` / `runsRecent` need no plural form (invariable nouns).
  All count call sites pass `{ count }`, so i18next plural selection fires.
- **Interpolation safety / dynamic keys** — no `t(\`...${x}\`)` anywhere; no string
  concatenation into `t()`. The only two dynamic lookups
  (`DirectoryPreview.tsx:352` `preview.source[r.source]`,
  `EnvPage.tsx:388` `env.source[row.source]`) index a closed TypeScript union
  (`"global" | "project" | "tool" | "default"`) whose every member exists as a key in
  both catalogs — a raw key can never render. `errors.*` dynamic resolution is
  deliberately whitelisted in `appError.ts`'s `KNOWN_MESSAGE_KEYS` with a comment, per
  `docs/agents/i18n.md`.
- **Error copy mapping** — every `AppError` code the Rust side can emit has a mapped,
  translated message in both locales: MISE_NOT_FOUND → `errors.miseNotFound`,
  MISE_TOO_OLD → `errors.miseTooOld` ({{found}}/{{minimum}}),
  TERMINAL_NOT_FOUND → `errors.terminalNotFound`, TIMEOUT → `errors.timeout`.
  `errors.unknown` is a sensible fallback and is unreachable-as-raw-key by construction
  (`resolveAppErrorMessage` resolves known keys, falls back to `errors.unknown` on a
  catalog miss, passes raw Rust detail verbatim otherwise). Raw stderr pass-through is
  honest: COMMAND_FAILED / PARSE_FAILED states show the verbatim stderr under copy that
  says "Stderr is shown below." — nothing is swallowed. All four UI sites that display
  `err.message` route through the resolver (verified by grep).
- **Retired vocabulary sweep** — "作用域", "上下文" and "项目" (as a domain noun) appear
  nowhere in user-facing copy; "Registry" appears only inside `tools.commandHint`
  ("mise registry · …"), which is command vocabulary in a command hint — explicitly
  allowed ("command/documentation vocabulary only", CONTEXT.md). `directory.eyebrow`
  correctly says "CURRENT DIRECTORY" / 「当前目录」.
- **Update-check panel (four states + idle, `appVersionCopy.ts`)** — every state names
  MiseDeck as the subject ("Check for MiseDeck updates", "Checking for MiseDeck
  updates…", "MiseDeck is up to date", "MiseDeck {{version}} is available", "Could not
  check for MiseDeck updates" + retry). A unit test asserts no state borrows mise's or
  a Tool's update wording. `about.download` is an external link to the Release page —
  ADR-0009's "stop at a link" honored.
- **Tone / voice (ui-ux-rules Copy section)** — sentence-case buttons, plain verbs, no
  ellipsis on buttons, confirmations echo the exact command, empty states carry their
  next step, status chips are lowercase and parallel ("running" / "ok · 3s" /
  "failed (3s, exit 1)"). The shared SuccessBar pattern ("{{tool}}@{{version}} installed
  and activated") matches the documented example verbatim.
- **zh punctuation habits** — full-width colon in `doctor.summary.labelWithColon`
  (「{{label}}：」 vs en "{{label}}:"), full-width parens in
  `execution.workingDirHome` (「~（主目录）」) and `errors.terminalNotFound`, 「、」
  separators, 「——」 em-dashes without spaces in body copy. This is careful work; the
  two exceptions are listed as P2.
- **Locale plumbing (`index.ts` / `useLanguage.tsx`)** — detection chain matches the
  documented precedence (localStorage → navigator → `fallbackLng: "en"`),
  `supportedLngs` mirrors `SUPPORTED_LANGUAGES`, `<html lang>` is reflected for
  `:lang(zh)` CSS. No findings.

## P1 — fix before GA

### P1-1 `errors.terminalNotFound` states a probe list that no longer exists (en + zh)

- **Current values**:
  - en: `"No terminal emulator was found on this Linux system (looked for gnome-terminal, konsole, xfce4-terminal)."`
  - zh: `"未在这个 Linux 系统上找到终端模拟器（已查找 gnome-terminal、konsole、xfce4-terminal）。"`
- **Evidence**: `src-tauri/src/shell.rs:640-688` now probes **ten** binaries
  (`x-terminal-emulator`, `kgx`, `ptyxis`, `gnome-terminal`, `konsole`, `xfce4-terminal`,
  `alacritty`, `kitty`, `wezterm`, `foot`) after beta17 #245. The copy still names the
  beta16-era three.
- **Consequence**: the error tells the user a false fact about their own machine — a
  data-honesty violation ("a wrong fact is worse than no fact"). A user running, say,
  only `kgx` is told it was never looked for.
- **Fix**: don't enumerate. "No terminal emulator was found on this Linux system." /
  「未在这个 Linux 系统上找到终端模拟器。」 (Optionally name the count: "looked for 10
  common terminals".) Enumeration in copy that must track a Rust table is drift waiting
  to happen; the sentence is actionable without the list because the copy already
  continues with the manual-command fallback at the call site.

### P1-2 `tools.upgradeChip` (en) calls a Tool's new version an "Update"

- **Current values**: en `"Update available · {{latest}}"` vs zh `"可升级 · {{latest}}"`.
- **Evidence**: CONTEXT.md (Update check): *"Unqualified 'update' means mise's own
  update (`mise self-update`); a Tool's newer version is an 'Upgrade'."* The chip sits
  on an outdated tool row whose own action button is "Upgrade" — the chip contradicts
  the button beside it. It also collides with `doctor.updateNotice.title`
  ("Update available"), which legitimately means *mise* — two different subjects, same
  English sentence, one app. zh is already correct.
- **Fix**: en → `"Upgrade available · {{latest}}"`.

### P1-3 `tools.success.unused` (en) uses the retired verb "removed" for an Unuse

- **Current values**: en `"{{tool}} removed"` vs zh `"{{tool}} 已取消使用"`.
- **Evidence**: CONTEXT.md (Unuse) lists _Avoid_: uninstall, remove, delete — at tool
  level. The SuccessBar is the result label of the Unuse action ("Unuse {{tool}}?"
  confirm, 「取消使用」 button); zh renders the approved term, en does not.
- **Fix**: en → `"{{tool}} unused"` (parallel to `tools.success.upgraded`
  "{{tool}} upgraded"). Body prose elsewhere ("it is removed from the config file",
  `tools.confirm.unuse.body`) describes the mechanism and is fine as-is.

### P1-4 `tools.orphan.tooltip` (zh) half-translates the approved term "配置文件"

- **Current value**: zh `"没有 Config 文件请求此工具"` (en: "No config file requests this
  tool").
- **Evidence**: the zh glossary's approved term is 「配置文件」 (CONTEXT.md: Config file
  （配置文件）), and the rest of the zh catalog uses it consistently —
  `preview.sections.config` 「配置文件」, `env.empty.bodyGlobal` 「写入会进入 mise 的全局
  配置」, `settings.tooltip.objectReadOnly` 「请直接编辑配置文件」. "Config 文件" is a
  hybrid that appears exactly once.
- **Fix**: zh → `"没有配置文件请求此工具"`.

## P2 — fix if cheap, or flagged for a decision

Grouped by class; each row names the exact key(s).

### P2-1 Outdated-hint verb doesn't name its subject (both locales) — decision

- `common.outdatedChecking`: en "Checking for updates…" / zh 「正在检查更新…」
- `common.outdatedError`: en "Could not check for updates" / zh 「无法检查更新」
- These describe `mise outdated` (Tools). Per the same glossary rule as P1-2,
  unqualified "update" is mise's own update — and this app has a *different* update
  check ("Check for MiseDeck updates"). The Tools toolbar momentarily reading
  "Checking for updates…" is the exact ambiguity the rule exists to prevent.
- **Recommendation** (owner decision): "Checking for outdated tools…" /
  「正在检查可升级的工具…」 and "Could not check for outdated tools" /
  「无法检查可升级的工具」. zh `common.outdatedCount` 「{{count}} 个工具可更新」 should
  move to 「可升级」 in the same pass.

### P2-2 `errors.timeout` names the object but no next step (both locales)

- en `"mise did not respond within the timeout."` / zh 「mise 未在超时时间内响应。」
- ui-ux-rules: error copy names the object, states the consequence, offers the in-GUI
  next step. There is no next step here, and no retry affordance rides along (unlike
  the outdated hint).
- **Recommendation**: append the recovery sentence, e.g. "Try the action again; if it
  keeps happening, run the command in a terminal to see more." /
  「请重试该操作；若反复出现，请在终端中运行该命令查看详情。」

### P2-3 `activation.bannerBodyUnknownShell` claims it "could not detect" a shell it names (both locales)

- en `"MiseDeck could not detect your shell ({{name}}). …"` /
  zh 「MiseDeck 无法识别你的 shell（{{name}}）。…」
- `{{name}}` is the raw *detected-but-unsupported* shell name (e.g. `nushell`, see
  `types/tauri.ts:202`). The sentence contradicts its own parenthetical: the shell was
  detected; MiseDeck simply has no rc-file rule for it.
- **Recommendation**: "MiseDeck doesn't know how to activate {{name}}. Add the
  appropriate `mise activate` line to its rc file…" / 「MiseDeck 不知道如何激活
  {{name}}。请在其 rc 文件中添加相应的 mise activate 行…」 (drop the `<shell>` placeholder
  prose; the line preview below already shows the concrete line).

### P2-4 `about.retry` diverges from `common.retry` — and the two locales diverge from each other

- en: `about.retry` "Try again" vs `common.retry` "Retry" — same action, two labels,
  in one app.
- zh: `about.retry` 「重试」 is *identical* to `common.retry` — so the catalogs disagree
  about whether this is one label or two.
- **Recommendation**: one decision, both locales. Either delete `about.retry` and use
  `common.retry` in `AppVersion.tsx:160`, or make both locales distinct deliberately
  ("Try again" / 「再试一次」) with a comment saying why.

### P2-5 `common.loadFailed` (en) — "the data" is stilted

- en `"Could not load the data"` vs zh 「无法加载数据」 (clean).
- **Recommendation**: en → "Could not load this data" or "Could not load data".

### P2-6 `states.notInstalled.body` (en) — telegraphic tail

- en: "… Guided install below runs the official install script through the execution
  panel; the install guide has the manual steps."
- Semicolon splice plus a predicate-less final clause. zh is fine
  (「安装指南提供了手动安装的步骤。」).
- **Recommendation**: en → "…; the install guide lists the manual steps."

### P2-7 zh 翻译腔 cluster (three keys)

- `env.tooltip.default`: 「继承自宿主环境」 — 「宿主」 is textbook translation-ese for
  "host". → 「继承自系统环境」.
- `settings.tooltip.objectReadOnly`: 「整表设置」 — → 「表类型设置」 (or keep mise's own
  "table" wording: 「表（table）类型设置」).
- `errors.miseNotFound`: 「请按 https://mise.jdx.dev/installing.html 安装后重新启动
  MiseDeck。」 — 「按 URL 安装」 is ungrammatical; a URL takes 访问/打开. →
  「请访问 https://mise.jdx.dev/installing.html 安装，然后重新启动 MiseDeck。」

### P2-8 zh execution count copy is awkward

- `execution.runsRecent`: 「{{count}} 条历史」 — 「条历史」 is not a natural collocation
  (en: "{{count}} recent"). → 「{{count}} 条运行记录」.
- `execution.runsRunning`: 「{{count}} 运行中」 — missing measure word, telegraphic
  (en: "{{count}} running"). → 「{{count}} 个命令运行中」.

### P2-9 `settings.empty.bodyShowAll` (zh) reuses the retired noun 「项目」

- zh: 「mise 的默认值仍然生效——此列表只显示显式设置的项目。」 — here 「项目」 means
  "items", not the retired project entity, but the word is banned from UI copy and its
  reappearance — even generically — re-teaches the retired vocabulary.
- **Fix**: 「此列表只显示显式设置过的项。」

### P2-10 `lockfile` vs approved term 「锁文件」 — decision

- `preview.hint` (zh): 「…配置文件与 lockfile。」 and `preview.lockfile.errorTitle`:
  「读取 lockfile 失败」.
- The zh glossary's approved term is 锁文件 (CONTEXT.md: Lockfile（锁文件）). The catalog
  ships the English loanword in Chinese copy. Defensible (mise's own docs say
  "lockfile"), but it is a terminology decision, not an oversight.
- **Recommendation**: owner picks one — 「锁文件（mise.lock）」 on first use per page, or
  an explicit "loanword allowed" note beside the glossary entry so future copy is
  consistent.

### P2-11 `home.rawLabel` untranslated in zh — decision

- en "RAW" / zh "RAW". It labels the collapsed `mise version --json` disclosure.
- **Recommendation**: 「原始输出」 (or keep RAW as a deliberate technical label — but
  then say so, because every other key in the catalog is translated).

### P2-12 zh em-dash convention exceptions (two keys)

- zh copy uses unspaced 「——」 throughout, but:
  - `about.triggerLabel`: 「MiseDeck {{version}} — 版本与更新」 (spaced single em dash)
  - `plugins.installForm.urlPlaceholder`: 「Git URL — github.com/<owner>/<repo>」
- **Recommendation**: 「——」 in the trigger label; the placeholder is a
  pattern specimen where the en-identical dash is tolerable, but 「Git URL：
  github.com/<owner>/<repo>」 reads better in zh.

### P2-13 zh colloquialisms (two keys)

- `tools.linkForm.explanation`: 「…会把它软链进 mise。」 — 「软链」 is dev slang. →
  「…会以符号链接（symlink）方式接入 mise。」
- `plugins.installedEmpty.body`: 「…去工具页搜索即可安装。」 — the page is named 「工具」;
  「工具页」 is casual. → 「…前往「工具」页搜索即可安装。」

### P2-14 `directory.recentsButton` is a terse label in both locales

- en "Recent" / zh 「最近」. The menu it opens is titled "Recent directories" /
  「最近的目录」 (`directory.recentsHeader`). A one-word button that is also an English
  adjective reads unfinished next to "Choose directory".
- **Recommendation**: "Recent directories" / 「最近的目录」 — or keep terse deliberately;
  low stakes either way.

### P2-15 `preview.empty.body` (en) brushes the retired "scope" vocabulary

- en: "The env and config sections already show the global resolution; this list is
  directory-scoped. …" — "directory-scoped" is an adjectival use, not the retired
  "scope switcher", but the safest copy avoids the word entirely.
- **Recommendation**: "this list is per-directory" / 「此列表按目录解析」 (zh is already
  clean).

### P2-16 rename-overwrite copy is vague about *whose* value wins (both locales)

- `env.confirm.renameOverwrite.body`: en "…the rename overwrites its current value with
  this one." — "this one" never names the value (it's `{{from}}`'s value moving to
  `{{to}}`). zh 「重命名会用新值覆盖它的现有值」 — 「新值」 is equally ambiguous.
- **Recommendation**: en "…overwrites its current value with the value of {{from}}." /
  zh 「…会用 {{from}} 的值覆盖它的现有值。」

### P2-17 `doctor.hint` (en) — "row tinting" is internal jargon

- en: "…the raw doctor output renders with row tinting." / zh 「…并按行着色。」 — both
  name a mechanism instead of the user-visible benefit.
- **Recommendation**: "…the raw doctor output renders with warnings highlighted." /
  「…原始 doctor 输出会高亮显示警告行。」

### P2-18 `plugins.installForm.explanation` (en) — "the CLI way" is casual idiom

- en: "Add a custom plugin the CLI way: …" — the app's voice elsewhere is plain and
  literal; this is the one idiom.
- **Recommendation**: "Add a custom plugin the way the CLI does: …" / zh 「按 CLI 的方
  式添加自定义插件：…」 (zh already matches this register).

### P2-19 `common.filter.noMatchBody` stutters the noun (both locales)

- en: "No rows match the current filter. Edit or clear the filter to bring the full
  list back." / zh 「当前过滤条件没有匹配任何行。修改或清除过滤条件即可恢复完整列表。」
- **Recommendation**: en "…Edit or clear it to bring the full list back." / zh 「…修改
  或清除它即可恢复完整列表。」

## Not statically decidable (flagged, not findings)

1. **Lockfile loanword (P2-10) and RAW label (P2-11)** — terminology decisions that
   need the owner's taste, not more analysis.
2. **Line-break behavior of the long zh strings** (e.g.
   `tasks.editForm.runReadonlyTooltip`, `states.tooOld.packageManagerHint`) — the
   "no orphan characters on a trailing line" rule (ui-ux-rules) can only be judged at
   rendered width; the copy itself is sound.
3. **Terminal names inside `errors.terminalNotFound`** — if the owner prefers keeping
   the enumeration after P1-1, the list must be generated from `shell.rs` or asserted
   by a test; a hand-maintained copy list will drift again.
