# 1.0.0-GA documentation static audit (2026-10-21)

> Background: pre-1.0.0-GA release audit commissioned by the product owner, documentation
> dimension. The app is open-source and the docs are its front door, so freshness and
> internal consistency are weighted accordingly.
> Baseline: master `37d27fb`, version `1.0.0-beta.17`, clean tree. Static audit only —
> no app launch, no builds; read-only greps, file reads, `git log`/`git tag`, `gh issue
> view` (read-only), and a link-resolution script over the doc set.
> Scope: `README.md` + `zh-CN/README.md`; `docs/design/*.md`; `docs/agents/*.md`;
> `docs/adr/0001–0009` + zh-CN mirrors; `CONTEXT.md` + mirror; `AGENTS.md` + mirror;
> `CLAUDE.md` + mirror; `.github/release-template.md` + mirror; `misedeck/README.md` +
> mirror. `HANDOFF.md` is exempt from mirroring by owner decision and was not audited.
> This file lives in `docs/feedback/` and is exempt from the zh-CN mirroring rule.

## Verdict summary

- **P0 = 1** — the release template ships a `brew install` command for a Homebrew tap that
  does not exist, plus a feature bullet for a page that was dissolved. It is the body of
  every lightweight-tag release, and `ci.md` calls it the recommended routine path.
- **P1 = 4** — README still wears its beta status line for a GA release; README's Windows
  note points at a closed issue and claims a fix that already shipped; `ci.md`'s artifact
  description is two releases stale (SHA256SUMS scheme, `ubuntu-latest` vs `ubuntu-22.04`);
  `product-logic.md`'s zh-CN link is dead.
- **P2 = 8** — stale inventories (CONTEXT version example, domain.md ADR list, i18n key
  groups, `npm run ci` description), a missing README line for the beta17 update-check
  feature, a wrong self-citation, the ADR-0002 tap decision, and a batch of nits.
- The design/ADR corpus itself is healthy: mirroring discipline holds across all 24 doc
  pairs (paired mtimes, bidirectional links, matching facts), and every rule doc I could
  check against code matched the code. The debt is concentrated in release-time artifacts
  and stale inventories, not in the product logic.

## P0 — blocks the 1.0.0 release

### P0-1 Release template instructs a nonexistent Homebrew tap and advertises a dissolved page (both locales)

- **Evidence**:
  - `.github/release-template.md:24` / `zh-CN/.github/release-template.md:24`:
    `brew install --cask cherishfall/tap/misedeck` — the tap does not exist.
    `docs/adr/0002-distribution-github-releases-and-homebrew-tap.md:5` status note:
    "the self-hosted Homebrew tap is **not yet implemented** — no tap publishing exists
    in CI". Verified: `.github/workflows/release.yml` has no tap/brew step anywhere.
  - `.github/release-template.md:83` (ci.md, "Annotated vs lightweight tags"): "The
    template is the recommended path for routine releases" — so a GA cut with a
    lightweight tag publishes install instructions that fail for every user
    (`Error: No available formula with the name "cherishfall/tap/misedeck"`).
  - `.github/release-template.md:9` / `zh-CN/.github/release-template.md:9`:
    "**Config editor**: form-based `[tools]` and `[env]` editing" — the Config editor
    page was dissolved; `docs/design/product-logic.md:66-72` ("The Config editor page is
    dissolved") and the code confirms only the `/config` → `/preview` redirect survives
    (`misedeck/src/main.tsx:76`). Release notes would advertise a page that does not exist.
- **Consequence**: the Release page is the first thing every GA user reads; a false
  install command there is the release-notes equivalent of a false README instruction.
- **Fix**: drop the brew block (or implement the tap first and then add it back), replace
  the Config-editor bullet with the shipped pages (Tools / Env / Preview), re-verify the
  zh mirror. If the tap stays unimplemented, also settle P2-8 (ADR-0002) in the same pass.

## P1 — fix before GA

### P1-1 README status line and beta framing must be rewritten for GA (both locales)

- **Evidence**:
  - `README.md:7` — "**Status: public beta, `v1.0.0-beta.17`** (16 builds since August
    2026). 1.0 is not final; copy and layout still change between betas."
    `zh-CN/README.md:7` mirrors it.
  - `README.md:135` / `zh-CN/README.md:135` — Known limitations still carries
    "Beta: UI copy and layout can change between releases."
  - This is release-blocking by the repo's own rule: `AGENTS.md:37` — "A release ships
    with a current README, in both locales. A stale README blocks the release"; repeated
    in the pre-tag checklist at `docs/agents/ci.md:55-60` (step 3).
- **What must change for GA**: version/build count in the status line; drop "public beta"
  and the "1.0 is not final" caveat; drop or rewrite the "Beta:" limitation; keep the
  platform claims (macOS Apple Silicon polished, Linux packaged-but-unverified, Windows
  experimental) only if they remain true at tag time.

### P1-2 README's Windows note is stale — #208 is closed and the fix shipped (both locales)

- **Evidence**:
  - `README.md:91` — "finding the mise binary on Windows is still being fixed
    ([#208](.../issues/208))"; `README.md:132` — "Windows is experimental ([#208])".
    `zh-CN/README.md:91,132` mirrors both.
  - Issue #208 is **CLOSED** (2026-10-20): "Windows 支持修复：locate_mise 跨平台探测 +
    Windows CI 冒烟". The fix is in the tree: `misedeck/src-tauri/src/mise.rs:138-198`
    (`candidate_paths` + full `PATH` scan, scoop/winget awareness), documented at
    `docs/agents/conventions.md:75`.
  - The live tracking issue for Windows/Linux verification is **#239** (OPEN: "beta17
    cross-platform spec：Windows / Linux 无真机静态审查产出").
- **Consequence**: a Windows user reading the README is told a landed fix is still being
  fixed, and is pointed at a closed issue.
- **Fix**: delete the "still being fixed" clause; keep "Windows is experimental — not yet
  verified on real hardware" and repoint it at #239.

### P1-3 ci.md's artifact description and release matrix are two releases stale (both locales)

- **Evidence**:
  - `docs/agents/ci.md:100-112` (en) / `zh-CN/docs/agents/ci.md:84-94` (zh):
    "A `SHA256SUMS` file **inside each artifact**" and "attaches their files (binaries +
    **the three `SHA256SUMS`**)". Reality since #251 (commits `b33c1c6`, `3a6ead3`):
    **one** release-wide `SHA256SUMS` computed in the release job over the merged
    artifact tree with bare basenames — `.github/workflows/release.yml:141-165`. The
    per-platform manifests were a shipped bug (beta.16's manifest covered Linux only);
    ci.md still documents the broken scheme.
  - `docs/agents/ci.md:14` (en) / `:13` (zh): "Builds Tauri bundles for `macos-latest`,
    `windows-latest`, `ubuntu-latest`" — `release.yml:40` builds on **ubuntu-22.04**
    since #247 (glibc portability).
  - Note: the README's SHA256SUMS instructions (`README.md:46`) are correct against the
    current workflow — ci.md is the stale document here.
- **Consequence**: `AGENTS.md:37` names ci.md's "Cutting a release" as the pre-tag
  checklist; a maintainer cutting GA gets a wrong picture of what the release produces.

### P1-4 product-logic.md's zh-CN link is dead (one `../` too many)

- **Evidence**: `docs/design/product-logic.md:3` —
  `> [简体中文](../../../zh-CN/docs/design/product-logic.md)` resolves **above the repo
  root**; the correct path is `../../zh-CN/docs/design/product-logic.md`. Verified by
  link-resolution script over the whole doc set: this is the only dead link in scope.
  The zh mirror's back-link (`zh-CN/docs/design/product-logic.md:3`) is correct.
- **Consequence**: violates the mandated bidirectional linking (`AGENTS.md:41`) in a doc
  every contributor is told to read before UI work (`AGENTS.md:17`).
