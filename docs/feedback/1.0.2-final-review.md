## 已实锤缺陷（按严重度）

### P0

**A. `ls-remote --json` 面板路径仍被 8 KiB 截断（#282 修复未覆盖 UI 实际路径）**
- 证据：`misedeck/src-tauri/src/mise.rs` — `PipeMode::Raw` 只接进 `run_mise_capture`（捕获读）；面板路径 `run_mise_command` → `run_mise_tracked_read_only` → `run_mise_timed` → `drive_child(..., PipeMode::Lines)`，单行 8 KiB 截断不变。UI 唯一的 ls-remote 入口是面板（`AddToolSection.tsx:218-225` `readIntoCache`，`background:true, readOnly:true`）；真实 go payload 17,388 B 单行 → `toJsonResult` 解析失败 → 版本管理区 Not installed 永久失败。**实机复现**：go 行「版本管理」→ Not installed 区渲染失败卡（r43-notinstalled-go.png）。
- 为何 CI 绿：#282 回归测试打的是 runner 函数（`mise_ls_remote`），从未经过 `run_mise_command` 边界。
- 修复方向：read_only 面板运行的 outcome.stdout 改走 Raw 捕获（≤2 MiB 聚合上限不变；面板 transcript 维持行视图 + typed truncation 事件），并在 `run_mise_command` 边界加单行大 payload 回归测试。

**B. MISE_SAFE=1 在当前 mise（2026.10.17）上静默丢弃项目 `[env]` 表变量 —— 目录模式 Env 页/概览页环境节缺数据；doctor 报告被污染**
- 实测：`MISE_SAFE=1 mise env --json[-extended] -C <dir>` 少返回项目 env 变量（本机复现，无 MISE_SAFE 则齐全）；`mise ls/tasks/config ls/outdated` 不受影响；`mise doctor` 在 MISE_SAFE 下多印一行 `MISE_SAFE=1` 进 env 列表且丢 dotfiles 段。
- 影响：目录模式 Env 页（IPC 探针实证 keys=4 vs 真实 5）；Overview 环境节同源；Doctor 报告（用户贴进 bug report 的东西）失真。`mise_command` 注释声称的 "emits the same data" 契约已失效（mise 行为随版本漂移）。
- 修复方向：**信任门控 safe 模式**——受信任目录与 Global 模式的读不注入 MISE_SAFE（与 mise 自身 trust 语义一致：trust 即"允许此配置执行"）；未信任目录维持 MISE_SAFE（数据可能不全，属 read-only 语义的一部分）。同步修正代码注释与相关测试前提； fixture 无法覆盖（外部契约漂移），补真实 mise 条件测试或以注释+文档记录。

**C. Tools 版本管理区 Not installed 失败卡渲染错误文案（命名了没跑过的命令 + 承诺未渲染的 stderr）**
- 证据：`AddToolSection.tsx:775-779` 复用 `states.commandFailed.*`（Home 版本门探针文案："mise version --json exited with a non-zero status. Stderr is shown below."）渲染 ls-remote 派发失败；实机截图（r43）确认文案出现且 stderr 未渲染。
- 修复方向：专用 key（命名 `mise ls-remote --json <tool>` / 通用化 "the command failed"）并渲染真实 error detail/stderr（PARSE_FAILED 携带 stderr）。

### v1.0.5（#309–#311）
