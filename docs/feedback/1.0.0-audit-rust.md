## Conclusion summary

| | Count | Reading |
| --- | --- | --- |
| **P0** | **0** | No data-loss, crash, or silently-wrong core path in the Rust layer. The runner cannot write files; the only destructive commands (`uninstall`/`unuse`) are explicit single-target argv built from a row the user picked. |
| **P1** | **3** | Two are platform-launch assumptions that a first-time user hits on the primary platform (macOS shell detection) and on Linux ("open in terminal"); one is a false "you are up to date" claim behind a captive portal. |
| **P2** | **15** | One hard contract violation (error code outside the fixed set), one systemic contract drift (messages are pre-rendered English), plus bounded leaks, redundant IPC payloads, PATH hygiene, and coverage gaps. |
| **OK** | 14 areas | Command inventory, panic safety, process-tree kill/reap semantics, timeouts, MISE_SAFE routing, argv/flag correctness against real mise, install echo parity, CSP/capabilities, wire shapes, cross-platform guards. Detailed below — the owner asked for the clean checks too. |

The debt is concentrated in three places, not spread evenly:

1. **The app is written as if it runs from a terminal.** Two of the three P1s
   come from environment facts that are true in `npm run tauri dev` and false
   in the shipped double-click experience (`$SHELL` on macOS; a terminal
   emulator that returns instead of staying in the foreground on Linux).
2. **The error contract is enforced in prose, not in types.** `AppError.code`
   has one illegal value pinned by a test; `AppError.message` is an English
   sentence at ~50 call sites even though `conventions.md` calls it an i18n key.
3. **"Pinned contract" argv is not wired.** The Rust argv builders that the
   docs call the single source of truth are test-only; the app dispatches
   strings duplicated in TypeScript, kept in sync by a comment.

Everything else — process teardown, timeouts, the streaming reader, MISE_SAFE
routing, and every mise flag against the installed 2026.10.15 CLI — is in good
shape and does not need to be touched for GA.

## P1 detail

### R-1 — macOS shell detection depends on a variable Finder launches do not set

**Evidence.** `detect_user_shell` reads `std::env::var_os("SHELL")` and returns
`ShellKind::Unknown { name: "unknown" }` when it is absent
(`shell.rs:149-169`, read at `:159`). There is no fallback to the user's login
shell (`getpwuid_r` / `dscl`), even though `libc` is already a unix dependency
(`Cargo.toml`, unix target) and `dirs::home_dir()` is used correctly elsewhere.

**Why it matters.** A `.app` launched from Finder or the Dock inherits the
launchd user-session environment, not a login shell's. On the audit machine the
user session has no `SHELL`:

```
$ launchctl getenv SHELL
(empty)
```

**Failure scenario.** Double-click `MiseDeck.app` → `shell_activation_check`
returns `Unknown` with `rcPath: ""` → `ActivationBanner` renders the *soft*
variant: "MiseDeck could not detect your shell (unknown)" plus
`eval "$(mise activate sh)"` (`ActivationBanner.tsx:91-131`,
`en.json` `activation.bannerBodyUnknownShell`). A zsh user who *is* activated is
shown the banner anyway (`activated: null` is falsy → banner renders), and a
user who is not activated is never told to edit `~/.zshrc` — the one thing the
banner exists to do. `detect_user_shell` also has no test (`tests/shell.rs`
only covers `classify_shell`), which is why this survived 17 betas: the dev loop
runs from a terminal, where `SHELL` is set.

**Fix.** On unix, after `$SHELL`, fall back to the passwd entry
(`libc::getpwuid_r(libc::getuid())` → `pw_shell`), then to
`/bin/zsh` / `/bin/bash` only if that is empty. Add a unit test that clears
`SHELL` and asserts the passwd fallback (requires the passwd read to be
injectable, or gate the assertion on a non-empty result).

**Confidence.** Static; the launchd environment was observed on this machine,
but the app itself was not launched (audit rule). Confirmation is in
"not verifiable" §1.

### R-2 — "Open in terminal" kills the terminal on Linux after 10 seconds

**Evidence.** `open_in_terminal`'s Linux branch builds argv for the first
available emulator and hands it to `run_prepared` (`shell.rs:798-810`).
`run_prepared` spawns the process, then **waits** for it under
`LAUNCH_TIMEOUT = 10s` and reports failure if it has not exited
(`shell.rs:865-899`); `wait_with_timeout` kills the child when the deadline
passes (`shell.rs:199-214`, kill at `:207-210`). The probe table includes
`kgx` (Ubuntu 24.04 default), `ptyxis` (Fedora 40+), `alacritty`, `kitty`,
`foot`, `wezterm`, `urxvt` — all of which run in the foreground until their
window closes, unlike `gnome-terminal` / `konsole` / `xfce4-terminal` which fork
to a server and exit immediately.

**Failure scenario.** Ubuntu 24.04 (no `gnome-terminal`), user clicks "Open in
terminal" → `kgx` opens a window at the right directory, the app keeps waiting,
at 10 s `child.kill()` closes the window, and the UI shows
`activation.openInTerminalError` ("Could not open a terminal at {{path}}…") for
a terminal that *did* open and was then closed by the app. The same happens with
kitty, alacritty, foot, wezterm and urxvt. `x-terminal-emulator` can resolve to
any of them.

**Fix.** Treat spawn success as success for emulators: `stdout/stderr/stdin` to
null and drop the `Child` without waiting (optionally `setsid`-detach so the
emulator is not in the app's group and is not killed by the exit sweep). Keep the
bounded wait only for the delegating wrappers that provably exit (`open -a` on
macOS, `cmd /c start` on Windows) — or drop it there too, since both return
immediately.

**Confidence.** Static; needs Linux hardware to confirm which emulators stay in
the foreground (see "not verifiable" §3). The code path itself is unambiguous.

### R-3 — A captive portal is reported as "MiseDeck is up to date"

**Evidence.** `fetch_feed` only checks `curl`'s exit status
(`update.rs:105-122`). `parse_release_tags` returns an empty `Vec` for anything
that is not a feed (`update.rs:131-148`), and `pick_newest` maps "no strictly
newer tag" to `None` (`update.rs:155-166`). `check` then returns `Ok(None)`
(`update.rs:77-80`), and `check_app_update` maps that to
`AppUpdateResult::Current` (`lib.rs:871-879`). The UI renders
`about.upToDate` = "MiseDeck is up to date" (`appVersionCopy.ts:44-50`,
`AppVersion.tsx:60-66`).

**Failure scenario.** User on a hotel/corporate network that intercepts TLS or
serves a 200 HTML block page → `curl -fsSL` succeeds → zero `<entry>` blocks →
the app states, with a green dot, that the build is current. ADR-0009 requires
every failure to "collapse into one sentence and a retry"; this failure instead
produces a confident false claim. The forward direction (a real feed with no
newer tag) is indistinguishable from "we never read a feed".

**Fix.** Distinguish "no feed" from "feed with nothing newer":
`parse_release_tags` returning empty → `Err(AppError::command_failed(...))`
(feed did not look like a release feed), or require the body to contain `<feed`
before parsing. `pick_newest` returning `None` with a non-empty tag list remains
`Current`. Add a fixture-based test for `check`/`parse` on an HTML body.

## P2 detail (the ones that need a scenario)

**R-4 — illegal error code.** `update.rs:108-120` constructs
`AppError::new("app_update_check_failed", …)`. `conventions.md:21-25` fixes the
set to six `SCREAMING_SNAKE` codes and calls a new one a bug. Today the UI
swallows it (`AppVersion.tsx:64-66` sets a generic error state), so nothing
renders it — but `tests/wire_shapes.rs:403-421` pins the illegal value, so a
future fix must touch the test too. Use `COMMAND_FAILED` with a key-shaped
message; keep curl's stderr (already preserved at `update.rs:116-120`).

**R-5 — messages are not i18n keys.** Only four messages are keys
(`mise.rs:91/97/111`, `shell.rs:813`). Everything else is English, e.g.
"cwd is not a directory: …" (`lib.rs:465-468`), "mise exited with status 1"
(`mise.rs:693-696`), "failed to read shell rc file: …" (`lib.rs:773-776`).
`resolveAppErrorMessage` passes non-key text through verbatim
(`utils/appError.ts:63-72`), so a zh-CN user sees English developer prose on the
activation banner (`activationContext.tsx:210`), the trust banner
(`trustContext.tsx:223`) and the preview's lockfile block
(`DirectoryPreview.tsx:497`). Repro: `chmod 000 ~/.zshrc`, launch, banner shows
"failed to read shell rc file: Permission denied (os error 13)". Either add
keys (`errors.rcUnreadable|path=…`) for the handful of user-facing messages, or
amend `conventions.md` to say raw detail text is allowed for
`COMMAND_FAILED`/`PARSE_FAILED` — an owner decision, but it should be written
down either way. `stderr` preservation itself is clean.

**R-6 — `None` is not a negative fact.** `shell.rs:498-505` returns
`Activated: None` for an undecodable rc file, with a doc comment
(`shell.rs:122-132`) telling the UI to render "—" and exclude it from status
derivation. `ActivationBanner.tsx:86` does `if (status.activated) return null`,
which is true for `null`, so the banner renders the full "Shell activation
missing … your config at <rcPath> does not have the mise activate line" for a
file the probe could not read. Repro: a legacy cp1252 profile with no BOM
(`decode_rc_bytes` → `Undecodable`). Fix in the banner (`=== true` / explicit
tri-state), and consider `null`-specific copy.

**R-7 — cancel-set leak.** `request_cancel` inserts into
`Registry::cancelled` (`process_tree.rs:190-196`); the only removal is
`unregister_locked` when the owning child is reaped (`:310-317`). A cancel that
loses the race with a normal exit — documented as "normal", and the JS always
fires it (`useExecution.ts:240-245`) — has no owner to remove it, so each such
click leaks a `String` for the process lifetime. Bounded by user clicks and
harmless in practice; a cheap fix is to bound the set (e.g. keep the last N) or
sweep entries older than the longest timeout.

**R-8 — self-update probe bypasses the read contract.**
`run_self_update` calls `run_mise` (`install.rs:304`), i.e.
`run_mise_tracked(..., STREAMING_TIMEOUT, safe_mode = false)`
(`mise.rs:650-663`). Post-update `mise version --json` is a read: it should use
the 10 s detect deadline and `MISE_SAFE=1`, like `detect_mise`
(`mise.rs:1777-1779`). Today a hung `mise version` extends a successful
self-update by up to 30 minutes before the panel resolves.

**R-9 — rc contents over IPC.** `ActivationStatus.rc_contents`
(`shell.rs:115-133`) carries the whole file text (up to whatever size) across
the IPC boundary on every launch (`:469-475`, `:489-495`). No component reads
it. Shell rc files routinely contain tokens and PATs; any script running in the
webview can call `shell_activation_check` and exfiltrate them. Drop the field or
cap it to the first N bytes; the UI only needs `rcPath` and `activated`.

**R-10 — trust fails open.** `check_trust` scans for lines ending in
`: trusted` / `: untrusted` and otherwise returns `NoConfig`
(`mise.rs:1241-1274`), which `useTrustGuard` treats as "nothing to trust,
mutations allowed". A mise release that prefixes a header, localises the words,
or changes the separator silently disables the trust gate (and the banner)
rather than surfacing an error. The format is only pinned by hand-written
fixtures (`tests/fixtures/mise/trust---show-*`). Fail closed: if stdout has
lines but none parse, return `COMMAND_FAILED` with the raw output.

**R-11 — PATH-resolved system tools on Windows.** `taskkill`
(`process_tree.rs:171`), `curl.exe` (`update.rs:92`), `powershell`
(`install.rs:64`) and `cmd.exe` (`shell.rs:601-613`) are spawned by bare name.
On Windows the `CreateProcess` search order includes the current directory, so a
binary planted where the app was started from is executed with the app's
privileges. Low likelihood (a bundled app's cwd is normally its install dir),
but it is a one-line class of fix on Windows: resolve `%SystemRoot%\System32\…`
explicitly, as the platform's own security guidance recommends.

**R-12 — "empty version means latest" is false.** `mise_install_argv`
(`mise.rs:1607-1618`) and its TS mirror (`ToolsPage.tsx:152-157`) both claim
`mise install <tool>` installs latest; `mise install --help` (2026.10.15) says
"a bare tool name installs the version your config requests for it". The branch
is currently unreachable (every `install` action carries a version picked from
a row), so this is a latent wrong-command bug plus a wrong comment. Either
delete the empty branch or emit `install <tool>@latest`.

**R-13 — argv is duplicated, not pinned.** The Rust builders
(`mise.rs:1584-1773`) are exercised only by `tests/tool_mutations.rs` /
`tests/tasks.rs`; the app dispatches the TS copies
(`ToolsPage.tsx:152-203`, `TasksPage`). ADR-0005 calls the Rust functions "the
pinned argv contract", but nothing fails when the TS copy drifts — the contract
is pinned against itself. Either expose a `build_argv` command (one source of
truth) or add a lint that parses both sides, like the install echo parity lint.

**R-14 — doctor runs twice on a finding.** `mise_doctor` retries in text mode
for `COMMAND_FAILED` (`mise.rs:1476-1478`) while its own comment says only a
*shape* failure justifies a re-run. `mise doctor` exits non-zero when it finds a
problem, so on a genuinely broken setup the app runs doctor twice (up to 2×120 s
with no cancel) and discards the structured JSON. Fixtures show warnings alone
exit 0 (`tests/fixtures/mise/doctor/exit_code`), so this only bites real errors.
Either narrow the guard to `PARSE_FAILED` or update the comment and accept the
double run deliberately.

**R-15 — unbounded feed buffer.** `cmd.output()` (`update.rs:105`) plus
`String::from_utf8_lossy` (`:122`) materialise the whole response; `--max-time 8`
bounds time, not bytes. A hostile or broken proxy on a fast link can push
hundreds of MB. Cap with `curl --max-filesize` (or truncate while parsing).

**R-16 — blocking `is_dir` on the async worker.** `validated_cwd`
(`lib.rs:455-473`) is called at the top of every `async` command
(e.g. `lib.rs:506`, `:529`, `:551`), before `spawn_blocking`, so a stat on a
disconnected network volume parks a tokio worker rather than a blocking-pool
thread. The same audit already moved `read_lockfile` off the main thread for
exactly this reason (`lib.rs:574-584`); move the check inside the
`spawn_blocking` closure too.

**R-17 — coverage gaps.** See the dedicated section.

**R-18 — stale terminal copy.** `errors.terminalNotFound` says the probe looked
for `gnome-terminal`, `konsole`, `xfce4-terminal`; the table now has eleven
entries (`shell.rs:638-697`). The message is shown precisely when nothing was
found, so it under-reports what was tried. Cheap copy fix in both locales.

## Checked clean (what was audited and passed)

These are as important as the findings — they are the areas that do **not** need
a GA ticket.

1. **Command inventory / dead commands.** All 22 `#[tauri::command]` functions
   are registered (`lib.rs:900-923`) and all 22 have a live caller:
   `detect_mise`, `directory_exists`, `tools_outdated`, `tools_env`, `env_ls`,
   `read_lockfile`, `config_files`, `trust_check`, `tasks_ls`, `doctor`,
   `registry`, `plugins_ls`, `shell_activation_check`, `open_in_terminal`,
   `set_window_theme`, `check_app_update`, `open_external`, `cancel_run` via
   `src/api/*.ts`; `run_mise_command`, `install_mise`, `mise_self_update`,
   `mise_trust` via the typed dispatch union at
   `useExecution.ts:214` (`"run_mise_command" | "install_mise" |
   "mise_self_update" | "mise_trust"`). **No dead commands.** Dead *runner*
   functions (`mise_ls`, `mise_ls_tool`, `mise_ls_remote`,
   `mise_tasks_edit_path`, `mise_settings_ls`, the argv builders) are
   documented as the pinned contract (ADR-0005) and tested — see R-13 for the
   caveat.
2. **Command contract shapes.** Every command returns either
   `Result<T, AppError>` or one of the documented `{kind:"ok"|"err"}` unions;
   `cancel_run` returns `()` by design (fire-and-forget, no failure channel);
   all boundary structs carry `#[serde(rename_all = "camelCase")]`
   (`mise.rs:57-79/241-271/706-764/950-962/1082-1116/1195-1211`,
   `shell.rs:56-68/113-133/563-576`, `install.rs:39-47/257-265`); every union
   variant is pinned in `tests/wire_shapes.rs`. No `#[serde(flatten)]` anywhere.
3. **Panic safety.** Every production `expect`/`unwrap` was traced to its
   precondition: `process_tree.rs:260` (`child()` is only called before
   `terminate_tree` on both owners, `mise.rs:521-522`,
   `install.rs:143-144`), `mise.rs:521-522` / `install.rs:143-144`
   (`Stdio::piped` is set immediately above), `shell.rs:800`
   (`linux_terminal_argv` always starts with the binary), `shell.rs:830`
   (fixed five-element plan), `shell.rs:855` (explicit empty check two lines
   above). `shell.rs:1037/1041` are test-only. No indexing or slicing panic:
   the byte offsets in `update.rs` (`entry_blocks`, `release_href`,
   `element_text`) and `external_link.rs` come from `find()` on ASCII needles,
   so they are char boundaries. A panic in a runner thread is contained by
   `spawn_blocking` and surfaces as `COMMAND_FAILED` (`lib.rs:487-499`).
   The `MISE_BINARY` mutex `.expect`s (`lib.rs:361/368/380/925`) can only fire
   if a panic happens *while* the lock is held, and the guarded sections are a
   `clone` and an assignment; cheap hardening is to use
   `unwrap_or_else(PoisonError::into_inner)` like `process_tree.rs:79-83`.
4. **Process management.** Children get their own session/group
   (`setsid` + `pre_exec`, `CREATE_NEW_PROCESS_GROUP|CREATE_NO_WINDOW` in one
   `creation_flags` call), kills are group kills with a `child.kill()`
   fallback, `try_wait` holds the registry lock across `waitpid` **and** the
   unregister so a reaped pid can never be signalled, `terminate_all` signals
   under the lock, `Drop` kills on panic, and `ExitRequested`/`Exit` both sweep
   (`process_tree.rs:89-123/212-217/275-308`; `lib.rs:950-953`). Cancel is a
   flag polled every ~50 ms, never a signal to a foreign pid
   (`process_tree.rs:184-201`; `mise.rs:540-552`). The only defect in the area
   is the leak in R-7.
5. **Timeouts.** `DETECT_TIMEOUT` 10 s, `READ_TIMEOUT` 120 s,
   `STREAMING_TIMEOUT` 30 min, install 5 min, probe 5 s, launch 10 s, update
   8 s (with a 5 s connect timeout), reader shutdown 1 s. Timeout always kills
   the tree, emits the `Exit { timed_out: true }` event and returns `TIMEOUT`.
   No `join()` is unbounded (`mise.rs:423-438`).
6. **Streaming.** Line splitting reads bytes until `\n`, strips `\r`, decodes
   lossily, and delivers a final unterminated line (`mise.rs:387-415`); both
   runners join readers *before* draining and share one 1 s bound
   (`mise.rs:553-565`, `install.rs:177-187`). Stderr is drained every loop
   slice, so a stderr-only command still streams.
7. **MISE_SAFE.** Set for every read (`run_mise_json` `mise.rs:788`,
   `detect_mise` `:1779`, `check_trust` `:1231`, `tasks edit --path` `:1166`,
   `doctor`/`registry` fallbacks `:1430`/`:1492`, `plugins ls` `:1560`,
   `settings ls` through `run_mise_json`), and deliberately absent from the
   streaming surface (`:662`, `:678`). Matches `architecture.md` → Trust. The
   one exception is R-8.
8. **mise invocation correctness.** Verified against the installed
   **2026.10.15** CLI: `-C/--cd` is a global flag accepted before the
   subcommand; `outdated --json --bump` (`-b, --bump`, `-J, --json`);
   `env --json` and `--json-extended`; `config ls --json`; `trust --show`;
   `tasks ls --json`; `tasks edit --path`; `tasks add [--description]
   [--depends] <TASK> [-- RUN]…`; `unuse <tool>` with the version omitted;
   `uninstall <tool>@<ver>`; `install <tool>@<ver>`; `link <TOOL@VERSION>
   <PATH>`; `upgrade [tool]` with no `--bump`; `settings ls
   --json-extended [--all] [--local]`; `settings set [--local] <k> <v>`;
   `ls-remote --json`; `self-update --yes`; `doctor --json`;
   `version --json`. No flag in the codebase is missing from the CLI, and no
   argv builder inserts a flag in the wrong position. The R-12 semantic
   mismatch is the only exception.
9. **Install.** Platform branch is derived from the same const the echo uses
   (`install.rs:53-56`); the Windows argv pins console encoding without changing
   the echoed line (`:76-109`); quoting is not needed because no user data
   reaches the shell string (fixed `curl`/`irm` one-liner); non-zero exit and
   timeout both map to failures with stderr preserved (`:199-231`); cancel
   kills the group so `curl` cannot keep writing shims (`:161-176`). Parity lint
   passes by construction (`scripts/check-install-echo-parity.ts` reads both
   files, sorts, compares).
10. **shell.rs detection tables.** Home is `dirs::home_dir()` in
    `rc_path_for`, `rc_sibling_paths` and `open_in_terminal`
    (`shell.rs:252-313`, `:738-755`) — no `$HOME`. rc paths per platform are
    correct (`.zshrc`/`.zshenv`, `.bashrc`+`.bash_profile`, fish config,
    pwsh 6/7 profile + Windows PowerShell 5.1 sibling), UTF-16 LE/BE + UTF-8 BOM
    decoding is correct and tested (`:356-388`, tests `:962-1026`), comments are
    skipped by the matcher (`:404-422`), and unknown shells return
    `activated: None` rather than a false negative on the Rust side. The
    PowerShell `Documents` path is still an assumption (see not-verifiable §4).
    R-1 and R-2 are the defects here; R-6 is a consumer-side defect.
11. **Security surface.** CSP is `default-src 'self'` with no remote loads
    (`index.html` self-hosts fonts; the inline theme bootstrap is hash-injected
    by Tauri). Capabilities are exactly what is used: `core:default`,
    `clipboard-manager:allow-write-text` (`utils/clipboard.ts:12`),
    `dialog:allow-open` (`directory/pickDirectory.ts:19`),
    `opener:allow-open-path` (`TasksPage.tsx:318/368`). Rust-side
    `open_url` bypasses the IPC ACL (`tauri-plugin-opener-2.5.4/src/lib.rs:62`
    → `open.rs:33`), which is why `open_external` works without
    `opener:allow-open-url`. The `{ "path": "**" }` scope entry is redundant
    (`glob::Pattern("**")` matches every path) and matches the documented
    "unscoped" decision; the `$HOME/**` entry can be deleted.
12. **external_link.** Scheme allowlist is case-insensitive, host is mandatory,
    `@`/`:`-only authorities are rejected, whitespace/control characters are
    rejected, length is capped, and the opener is never given a shell
    (`external_link.rs:40-93`, tests `:99-181`).
13. **update.rs parsing.** Truncated entries are dropped rather than guessed,
    unterminated `</entry>` stops the scan, empty/garbage bodies yield zero
    tags, unparsable tags and unparsable current versions never fabricate an
    update, and semver ordering handles `beta.17 > beta.16` and
    `1.0.0 > 1.0.0-beta.17` with `semver::Version::cmp`
    (`update.rs:131-220`, tests `:245-348`). No panics on odd input. R-3/R-4/
    R-15 are the gaps.
14. **Cross-platform guards.** No macOS-only behaviour leaks into
    Windows/Linux paths: the accessibility `objc` block is `cfg(macos)`
    (`lib.rs:954-968`), `set_background_color` is `cfg(macos)`
    (`lib.rs:828-843`), the Windows flag word is a single `creation_flags` call,
    `hide_console_window` is a no-op off Windows, and `open_in_terminal`'s
    three branches are `cfg`-exclusive. The only cosmetic leak is
    `platform: "Linux"` on non-macOS unixes (`shell.rs:805`), which also affects
    the FreeBSD install branch (`install.rs:55-56`), but nothing else keys off
    that string.

## Test coverage vs. conventions (fixture-mise pattern)

The seam is honoured: 14 integration suites drive `tests/fixtures/mise/fixture-mise`
and never touch the real CLI; pure builders are unit-tested; `wire_shapes.rs`
pins every boundary enum. Nothing below is a test *failure* — these are
production behaviours with **no** test at all:

| Gap | Evidence | Why it matters |
| --- | --- | --- |
| `run_install` itself | `install.rs:390-467` spawns `sh` directly and re-implements the loop; `run_install` is never called from a test | Cancel, timeout, non-zero mapping and the `stdout`/`stderr` aggregate of the guided install are unexercised — the one path a user without mise takes on day one |
| `detect_user_shell` | `tests/shell.rs:45-80` covers `classify_shell` only | Hides R-1 |
| Lockfile ancestry walk | `tests/directory.rs:163-200` only checks the same directory; `lockfile_path` (`mise.rs:916-926`) has no test | A subdirectory of a project with `mise.lock` is the case #230 fixed; a regression would be invisible |
| `MISE_SAFE` contract | zero references in `tests/` | The trust guarantee lives in an `if` with no assertion; a refactor that drops `cmd.env` would pass every test |
| `update::check` / `fetch_feed` | `tests/` tests only `parse_release_tags` and `pick_newest` | The curl invocation, exit-status mapping, lossy decode and R-3's "empty feed" branch are untested |
| `open_external::open` | `external_link.rs:99-181` tests `validate` only | The opener call and its error mapping are untested (hard without an `AppHandle`; at least assert `open` rejects invalid input) |
| `set_window_theme`, `cancel_run`, `check_app_update` | Tauri-level | Acceptable without a harness; call out in the handoff |
| Doctor double-run | no fixture for `doctor --json` + non-zero | R-14 is only visible by reading |

## Not verifiable without hardware / a launched build (by audit rule)

1. **macOS Finder launch and `$SHELL` (R-1).** `launchctl getenv SHELL` is
   empty on the audit machine, which is strong evidence, but the app itself was
   not launched. Confirm by double-clicking the beta.17 `.app` and reading the
   activation banner / `shell_activation_check` output.
2. **`open -a Terminal <path>` landing directory.** The comment at
   `shell.rs:523-531` claims the window lands in `$HOME` because `open -a` has no
   `--working-directory`; the argv passes the path as the document argument
   (`shell.rs:760-773`) and the success copy promises "Opened Terminal.app at
   {{path}}" (`en.json` `activation.openInTerminalSuccess`). One of the two is
   wrong; only a real launch settles it. (If the path is honoured, delete the
   stale comment.)
3. **Linux terminal foreground behaviour (R-2).** Which of `kgx`, `ptyxis`,
   `kitty`, `alacritty`, `foot`, `wezterm`, `urxvt` return immediately is a
   per-version fact; none exists on this machine. The `wait_with_timeout` +
   `kill` path is unambiguous in code.
4. **Windows PowerShell profile location.** `dirs::home_dir()/Documents/...`
   (`shell.rs:276-278`) is wrong when OneDrive redirects the Documents known
   folder. No Windows machine in the loop; the Windows CI leg only proves the
   path is *constructed*, not that it exists.
5. **`mise trust --show` exact output on 2026.10.15.** The parser
   (`mise.rs:1254-1269`) is pinned only by hand-written fixtures. Running it
   was out of scope (static rule); worth one manual line before GA because
   R-10 is a security-relevant fail-open.
6. **`mise doctor --json` exit code when a real error is found.** Help says
   doctor exits 1 on a problem; fixtures only cover warnings (exit 0). Decides
   whether R-14 is a real double-run on broken setups.
7. **Table headers** in `mise registry` / `mise plugins ls --urls` on
   2026.10.15 (`mise.rs:1499-1510`, `:1567-1580`). A header row would become a
   phantom registry/plugin row. Current fixtures have none.
8. **`open_in_terminal` on Wayland / xdg-desktop-portal-less desktops**, and
   whether `which_exists`'s `--version` probe ever opens a window for an
   emulator that rejects the flag.
